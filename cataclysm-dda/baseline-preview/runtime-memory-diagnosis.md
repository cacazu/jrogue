## Measured failure and remaining attribution gap

The fresh corrected-package session is archived at `browser-qa/output/2026-10-02T19-30-37-264Z/evidence.json`. It started with **6,146,662,400 B physical available** and **6,980,669,440 B commit headroom**. The actual pre-data page metric at 19:31:26.564 UTC records native linear memory **536,870,912 B**, CDP JS heap used **10,548,896 B**, and backing storage **182,784,871 B**. These measure different ownership domains; do not add them as if they were equivalent physical resident bytes.

Immediately before native custom creation, owned Chrome private was **1,238,962,176 B**. At 19:32:54.205 UTC it reached **3,578,896,384 B**, a **2,339,934,208 B** step, while physical available fell to **2,078,232,576 B** and commit headroom to **2,574,352,384 B**. The **2 GiB physical floor** triggered; the unchanged **5 GiB owned-private cap** did not. All eight recorded Chrome identities subsequently closed. No native exception, WASM allocation error or target crash was observed.

The page thread was busy during creation, so no post-Enter JS heap/linear-memory metric was available before the guard terminated it. This evidence does not attribute the step to native world data, graphics, catalog indexes, WASM compilation or a particular allocator. A 19.28 MiB transient MO reduction cannot be presented as resolving a multi-GiB, later allocation step. Root is investigating the separate Chrome/V8 compilation mode. Full game creation/play/save/resume and revised mobile layout remain unverified.

## Conditional restart bounds

From session start to its censored final sample, net system headroom consumption was **4,068,429,824 B physical** and **4,406,317,056 B commit**. Merely reproducing that observed consumption while retaining the 2 GiB floors would require initial headroom above **6,215,913,472 B physical (5.789 GiB)** and **6,553,800,704 B commit (6.104 GiB)**, before any margin. These are **observational lower bounds**, include concurrent system activity, and say nothing about the unobserved full-game peak. The previous 4/6 GiB launch gate did not cover this measured phase.

The browser owner's parent-reviewed experimental mode currently requires a **fresh 7 GiB physical / 9 GiB commit** gate, preserves **5 GiB owned Chrome** and **2 GiB remaining** limits, and will launch only after the parent coordinates the shared executor. No unconditional relaunch is authorized by this note. A read-only snapshot at **19:42:25.877 UTC** observed **7,573,278,720 B physical (7.053 GiB)** and **9,259,372,544 B commit (8.623 GiB)**. That snapshot misses the 9 GiB commit requirement and is not a launch approval; `post-qa-resource-snapshot.json` retains it. Re-measure immediately before any explicitly coordinated run, preserve the original data/source/manifest, and stop only verified owned browser identities if a floor is reached.
