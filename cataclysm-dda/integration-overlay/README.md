# Live input snapshot source preparation

**Two C++ translation units compiled; live boundary unconnected; standalone Rust consumer tested.** This directory prepares a bounded observation
boundary for original Cataclysm: DDA 0.I-1, commit
`7b2efa5cea38e4d4d97dd0e63b28b9148623da59`. It has not changed the current
engine build, pristine source, baseline shell, Rust bridge, or accepted baseline artifacts.
The lightweight checks validate source pins and patch construction; they do not
validate C++ compilation, original-engine/Rust WASM behavior, or gameplay. One
isolated 61-byte predeclared WASM import fixture checks the unsigned notification
boundary only; it is separate from both prepared modules.

The patched `input_context.cpp` and new `browser_input_snapshot.cpp` subsequently
compiled as two isolated wasm32 objects with the accepted baseline flags and
frozen SDK. [Actual compile proof](build-plan/cpp-compile/compile-verification.json)
records 145/4 pinned non-system dependencies, diagnostics, artifact hashes and
closed owned jobs. Compilation took 17.687/2.085 seconds, with job-private peaks
368,955,392/83,496,960 bytes. This proves translation-unit/type/access and compiler
handling only; no final linking, producer execution, native notification or
engine/Rust/browser integration occurred. Baseline objects/package remain intact.

The separate native Rust snapshot consumer subsequently passed **19/19 tests**
with exact cached dependencies, `--offline --locked`, one worker and one test
thread. [Current consumer proof](build-plan/consumer-verification.json) records
commands, compiled-source/fixture/lock hashes, output and guarded resource
measurements. These tests execute the real standalone Rust parser, owned
records, release/state handling and denied-command policy against synthetic
JSON fixtures and `FakeTransport`. They do not execute the original C++
serializer, four exports, host heap copy, Asyncify scheduling or native binding
precedence. Final linking, real-engine/FFI/browser integration and
state/RNG purity remain pending. Historical `SOURCE-REVIEW.md` and
`SOURCE-PREPARATION.json` retain their original preparation-stage claims.

Phase 1 adds a scoped publication inside the existing
`input_context::handle_input(const int)` wait and one small translation unit.
The four C exports pin an immutable owned UTF-8 JSON snapshot, return its bytes
and length, and release the pin. A deferred JavaScript notification announces
availability. The original C++ input loop and gameplay remain authoritative.
There is no action queue, save operation, new game loop, terrain renderer,
connected Rust context consumer, or accepted-input event stream in this preparation.

## Files

- `src/browser_input_snapshot.h/.cpp`: owned snapshot storage, serialization,
  scope restoration, four C exports, and bounded notification.
- `hook-input-wait.inc`: the exact insertion in the original wait. Its internal
  noncapturing member-defined callbacks reuse existing private access and
  `input_manager` friendship. No original class header changes are needed.
- `generate-overlay.mjs`: verifies five exact original source hashes and writes
  `generated/src/`, `live-input-snapshot.patch`, and `SOURCE-PREPARATION.json`.
- `validate-source.mjs`: checks source pins, hook placement, generated bytes,
  exact in-memory forward/reverse patch application, and the bounded source ABI.
- `ABI.md`: the observation contract and future integration/test requirements.
- `SOURCE-REVIEW.md`: source review findings and their limits.

## Integration after the reserved engine build

These are review instructions, not actions performed here.

1. Make a complete isolated port source copy of the pinned source. Validate its
   original hashes before applying `live-input-snapshot.patch` to that copy.
   Apply with a patch tool's check step first. The reverse patch must restore
   the original `src/input_context.cpp` exactly and remove the two additions.
   Never patch the pristine source or active build tree.
2. Compile that copy's patched `src/input_context.cpp` and new
   `src/browser_input_snapshot.cpp`, with the new header in that same `src/`.
   Add `CDDA_BROWSER_INPUT_SNAPSHOT_BUILD_ID` as an explicit C++ string-literal
   macro, identifying this source patch and the build configuration. Keep the
   original compiler, ABI, exception, SDL, Asyncify, and single-thread settings.
   The module catches its own serialization/allocation failures. Compilation
   and exception-policy compatibility still require validation.
3. Add the following four names to the existing Emscripten export list without
   dropping its current exports:
   `_cdda_browser_snapshot_pin`, `_cdda_browser_snapshot_data`,
   `_cdda_browser_snapshot_size`, `_cdda_browser_snapshot_release`.
   The included `EM_JS` notification uses the original module's JavaScript
   glue. Build this source exactly once. Confirm that these functions remain
   linked and that heap views are available to the future host adapter.
4. Build in a separate output tree with fresh dependency information. Do not
   blindly reuse original objects. C++ quoted headers search the including
   file's sibling directory before an `-I` overlay: an untouched pristine
   `src/*.cpp` plus only `-I integration-overlay` is not a consistent header
   replacement strategy. This slice does not modify `input.h` or
   `input_context.h`; any future header changes require the complete isolated
   source copy, or a proven equivalent consistent overlay, and recompilation
   of every affected dependency to avoid differing class definitions/ODR bugs.
5. First connect only a host observer which copies pinned bytes and releases
   every pin in `finally`. Require schema/build identity and matching
   publication generation. Keep native input working when snapshots fail or
   are unsupported. Only then add a separately reviewed pure Rust parser and
   control renderer; do not use this snapshot to execute gameplay commands.

The actual source boundary and weather/RNG release blocker are documented in
[CPP-RUST-BOUNDARY-NEXT.md](../docs/CPP-RUST-BOUNDARY-NEXT.md). The separate
[SEMANTIC-TEXT-INTEGRATION.md](../docs/SEMANTIC-TEXT-INTEGRATION.md) owns the next
14-message help/keybinding consumer and typed semantic text records. Phase 1
exports source action IDs and binding descriptors, not translated action names.

## Outstanding acceptance

The next isolated engine candidate must link and execute the original engine with this
patch. Real-engine tests must exercise nested waits, keybinding edits and empty
overrides, missing actions without native map insertion, `STRING_INPUT` raw
Unicode/IME, timeout restoration, bounded failures, pin lifetime and heap
growth, and unchanged native physical input. Repeated observation must leave
turn state, gameplay RNG, and native action-context tables unchanged. These
checks remain open. Isolated Rust tests and this source validator do not prove
whole-game rendering purity or browser/mobile/full-save acceptance.

The preparation check completed with 1,206 lightweight assertions, including
exact in-memory forward and reverse unified-patch application and unchanged
five-file upstream pins. Both Node scripts passed `node --check`. A tiny
predeclared WASM i32-import fixture demonstrated signed high-bit host arguments;
the actual notice expression then passed unsigned reconstruction for 16 half
pairs. Results in `SOURCE-CHECKS.json` explicitly scope this runtime evidence to
that isolated boundary fixture. Those original preparation checks executed
neither prepared C++ nor Rust; subsequent compile/consumer evidence is above.
The corrected 21,433-byte patch SHA-256 is
`897d37e0aea8a37ebfc970411a3be29d45624f9fd2f752cb9271a4251ffd9392`.

A separate [Rust consumer preparation](rust-snapshot-consumer/README.md) now
contains the genuine typed owned parser and safe transport/ordering contract.
Its three synthetic fixtures passed 218 Node fixture/provenance assertions;
19 Rust tests subsequently compiled and passed against synthetic fixtures and
`FakeTransport`. It has no live host
adapter, WASM export surface, renderer, or command authorization. Existing
compiled bridge artifacts and their source hashes remain unchanged.

Native readers that bypass `input_context::handle_input`, including direct SDL
or ImGui waits, are not tracked. A parent tracked wait can remain published
while such a reader is active. Therefore this slice alone is not an authoritative
map of every active UI context and must not authorize helper command execution.
Weather animation still consumes gameplay RNG while waiting for input; this
overlay neither fixes nor conceals that release blocker.
