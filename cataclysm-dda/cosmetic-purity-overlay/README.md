`cpp/cdda_presentation_hash.h` has no engine, clock, mutable static, world lookup, I/O or retained random counter. It computes a deterministic u32 key with length-prefixed UTF-8, canonical little-endian signed-coordinate words, distinct versioned weather/NPC domains, FNV byte accumulation and wrapping-u32 diffusion. NPC selection returns true for native chance≤1. For larger chances, a pure local enumeration rejects the incomplete residue interval before testing residue zero of `[0,chance−1]`. Odd stride plus bijective u32 diffusion guarantees a qualifying word in at most **threshold + 1** iterations; this is a finite mathematical bound and **not** a small worst-case latency guarantee. No enumeration state survives the call. C++/Rust numeric assumptions and constants are explicit.

Accepted-word rejection removes unequal residue populations caused by direct modulo over all u32 words. Deterministic observed-frame hashes do **not** establish statistical uniformity over real frames, independence of candidates, or exact native stochastic `1/n` reservoir probabilities. The preserved behavior is the native admission/count/equality/range/zero-residue/color-selection structure. Visual choices deliberately change: the same tile ID and coordinates choose the same static sprite on repeated redraw; the same admitted collision inputs choose the same NPC color decision. View or candidate data can change that choice. There is no artificial frame epoch in the existing `weather_printable` structure, and this overlay adds none. Static weather redraw flicker caused solely by RNG therefore becomes stable; animated tiles still use their native clock phase.

Removing these cosmetic calls deliberately changes the global RNG trace compared with pristine upstream, including calls that were formerly made for single-sprite weather tiles. `rng_bits()` and `rng()` use standard distributions over the shared native engine: one API call is not asserted to equal one engine advance. Existing pristine seed/replay fixtures and old RNG-capsule checkpoints cannot be assumed compatible. A combined build needs a distinct provenance/build identity and new validated replay baseline; no save version or checkpoint format is silently changed here.

`rust/` is an isolated presentation crate with no dependencies, unsafe code, FFI, gameplay state or platform access. It consumes immutable weather or already-admitted collision records. Its weather consumer implements only nonanimated native lookup3 and weighted-list selection over observed nonnegative native-order weights with checked int-range totals. Animated phase, texture lookup, rotation and drawing are explicitly outside that Rust subset. Its generic color consumer applies only the native collision branch; it does not collect NPCs, perform visibility tests, increment counts or deduplicate followers. All five golden/bounds/equality/repetition tests in `rust/src/tests.rs` passed on the native GNU Rust target. They do not link the shared `rust-contracts` packages or execute native C++ callers. Followers outputs, exact NPC-key goldens, the third empty-ID weather fixture and complete native/Rust fixture-set parity still need explicit assertions/harness execution.
