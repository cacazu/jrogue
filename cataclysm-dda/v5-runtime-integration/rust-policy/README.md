# Native-v5 platform policy

This dependency-free Rust crate implements a pure platform boundary for the retained original C++ game. It pins the six Combined Ready files in the reviewed parent handoff and describes three native string defaults for new profiles. It has no gameplay, RNG, clock, file, browser, or storage access. It does not claim artwork or full-game verification.

The host computes SHA-256 over each exact file buffer and passes its byte length and eight digest words in big-endian SHA-256 order. The Rust policy compares those values with immutable expected metadata. It does not perform cryptography, accept host pointers, or allocate. The host must check all six identities before writing any tileset file. The required order is core-functional.png, core-tiles.png, overmap-functional.png, overmap-tiles.png, tile_config.json, tileset.txt.

The five exported scalar calls are cdda_v5_policy_version (1), cdda_v5_asset_count (6), cdda_v5_validate_asset (0 accepted, 1 bad index, 2 bad length, 3 bad digest), cdda_v5_new_profile_option_count (3), and cdda_v5_new_profile_option_kind (1 language, 2 tiles, 3 overmap tiles, 0 invalid). The validator accepts index, bytes, and eight separate u32 digest words. Rejection precedence is index, length, digest.

Language maps to USE_LANG=ja; tiles and overmap tiles map to cdda16_combined_ready. All three are strings. Original C++ boolean defaults are inherited. The pure profile helper returns no instructions for an existing profile; the JavaScript adapter remains responsible for determining restored profile presence after original C++ IDBFS synchronization and preserving existing option bytes exactly. The policy cannot read or rewrite restored profile bytes.

Source validation reads all six actual parent files and checks size, SHA, order, Rust constants, independent hexadecimal test fixtures, scalar ABI, empty dependencies, and the three option names/types. Five genuine native Rust tests passed for all six identities; every digest bit and ordering; malformed lengths/indices and precedence; native string defaults; and existing-profile no-write/repeated-call purity. Pure owner source tests check 17 report-parser, explicit-release, hash, and resource-boundary cases. Source checks are distinct from compiled Rust, host integration, and real game tests.

The four exact compiler commands are frozen in quality-plan.json: package fmt --check (including the child test module), five GNU native tests, package Clippy -D warnings, and wasm32-unknown-unknown release build. They use offline/locked/jobs1, a new owned-target, the already reviewed CPP2/run_owned guard, a fresh 4/6 GiB launch gate with browser 7/9 priority, 1 GiB owned private/working-set caps, 2 GiB global floors, and 180 seconds per stage. No command launches without root window release and the exact current owner SHA. Source validation does not load a Windows job guard or launch Cargo.
