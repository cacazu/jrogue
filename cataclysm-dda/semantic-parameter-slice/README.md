# Source-bound named parameters

Three of the twelve `printf-parameters-need-named-schema` exclusions now have separate English/Japanese catalogs using the existing Rust `Term { id, count }` parameter, with count exactly one. This preparation preserves the existing public message IDs and does not change the pristine game, frozen catalogs, shared contracts or browser package.

| Existing message ID | Named parameter | Original producer |
| --- | --- | --- |
| `cdda.character_creation.profession.requirement_completed` | `achievement_name` | `assemble_profession_details`; requirement achievement translation leaf; the format includes its original final newline |
| `cdda.character_creation.scenario.requirement_completed` | `achievement_name` | `assemble_scenario_details`; requirement achievement translation leaf; the format has no final newline |
| `cdda.core.fault.fault_blade_cracked.description` | `item_type_name` | `item::get_fault_description`; base `itype::nname(1)`, without instance or variant display-name assembly |

Exact original English/Japanese strings, native source/argument expressions, JSON pointers, source hashes, observed definition ownership and surrounding green color/newline assembly are recorded in `output/source-inventory.json`. All sources are pinned to official Cataclysm:DDA 0.I-1 commit `7b2efa5cea38e4d4d97dd0e63b28b9148623da59`. `output/en.json` and `output/ja.json` contain only these three message templates. The two separately named term-fixture catalogs contain existing achievement/item leaves selected synthetically to exercise the formatter; they do not establish that a real character requirement or item fault uses those particular definitions.

Nine messages remain excluded in `output/remaining-blockers.json`. The dangerous-field message needs rich color structure and the selected field intensity identity. The two ranged actions need typed key bindings plus recursive item display-name structure. The six Android attack messages need visibility/name/article/decorations, receiver-specific `<npcname>` substitution after printf, and actual routing/suppression timing. The NPC branch may receive a monster. An evaluated second body-part printf argument is unused in all six message templates. Player-provided nicknames are external text; unique/fused names have unaudited ownership and are not classified as external text. These structures cannot be represented faithfully by the current plain-text catalog's zero-parameter Term leaves, Count or UserText.

The prepared Rust adapter receives an existing TextId already resolved by a caller from an observed loaded definition. A syntactically valid TextId does not attest native identity, lifecycle, overrides or applicability. Actual definition registration/lookup, original producer annotations, C++ to Rust FFI, runtime merge/locale switching and browser consumption remain unconnected. No C++ patch is applied or claimed by this increment.
