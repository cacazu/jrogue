# Original Cataclysm: DDA browser QA

This harness exercises the actual linked C++ engine and its isolated local browser package. It does not claim that an unconnected Rust frontend passes gameplay tests.

Prerequisites: `baseline-preview/web/package-manifest.json`, all runtime files, and the loopback package server. The harness checks those prerequisites before starting Chrome. It uses installed Node and Chrome, no downloaded browser or dependencies, one headless browser, and a unique profile under this directory. Only its own Chrome process is closed.

After the parent grants the browser window and the package owner confirms packing has exited and runtime verification passed, set `CDDA_BROWSER_SLOT=parent-coordinated`, `CDDA_BROWSER_PRIVATE_BUDGET_BYTES=4294967296`, and `CDDA_BROWSER_REMAINING_FLOOR_BYTES=2147483648` in the QA process. Start `node browser-qa/session.mjs http://127.0.0.1:8878/ --prepare-only` to record exact streamed package hashes, selected candidate, isolated profile and fresh memory without Chrome. Report that `pre-launch.json` to the coordinator, then run the same command with `--prepared <absolute pre-launch.json path>` and without `--prepare-only`. The launch repeats the fresh **4 GiB physical / 6 GiB commit** gate. No second approval wait is needed within the granted window.

The real-game guard caps the owned Chrome tree at **4 GiB private memory**, requires **2 GiB physical/commit remaining**, and stops only processes whose PID/profile/start identity matches its recorded tree. It imposes a 30-minute session deadline and records sampled memory; samples are not continuous peak measurements. A guard failure closes the owned test session and preserves evidence. Only the QA control server on 8890 is closed; the package owner's local game server remains available.

The session starts a bounded CDP control server at `http://127.0.0.1:8890/`. Send JSON commands with `node browser-qa/control.mjs '{"op":"capture","name":"desktop-menu"}'` or a JSON file with `--file`. Operations include `status`, `eval`, `key`, `keys`, `text`, `compose`, `click`, `tap`, `capture`, `viewport`, `reload`, `files`, `export`, `network`, `record`, and `close`. The control server and browser are local only. Arbitrary evaluation is limited to the isolated browser test profile. Native text/composition event submission is not a pass until its actual onscreen/native-file result is verified.

Evidence is written after every operation under `output/<timestamp>/`. It includes package hashes, browser version, command results, bounded runtime exceptions and failed requests, canvas/layout diagnostics, native-file hashes, screenshots, and owned PID. Screenshots require visual inspection; viewport fit does not prove Japanese glyph readability. Native save comparisons require actual game save and reload commands, not just a shell export.

The `export` operation requires the original game to have saved first, records native file hashes, downloads the actual version-1 JSON archive through Chrome, validates its source commit/format/base64 sizes, and compares exact raw file paths and bytes. It proves container fidelity only when those checks actually pass. The shell currently has no archive import operation: restore acceptance concerns original IDBFS reload/resume, not an invented archive import. Save-file version metadata and unchanged player names must be checked separately.

Planned original-game checks are tracked in [QA-PLAN.md](QA-PLAN.md). Native gameplay/RNG state hooks are absent; no source fixture, generic shell assertion, screenshot hash, or native-save file hash will substitute for a gameplay pass. Determinism and render purity require the real core bridge and RNG capsule and remain untested until connected.

Limitations: Chrome desktop mobile emulation is not a physical phone or mobile browser; SwiftShader is a software WebGL renderer; a generated character name is game content whereas a deliberately typed player name must remain literal. The original C++ reference frontend has a bounded Rust shell/helper bridge. It does not establish complete Rust UI/input migration, full semantic-ID gameplay integration, full translation coverage, gamepad/physical IME support, audio acceptance, or whole-game completion. Sound is disabled in this reference engine. Delivery is the requested Node localhost HTML; remote hosting is outside current scope.
