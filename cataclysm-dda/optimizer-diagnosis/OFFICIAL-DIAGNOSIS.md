## What the implementation supports

Asyncify must transform functions that can be on a suspended stack. Indirect calls limit its static analysis; manual `ONLY`, `REMOVE`, and `IGNORE_INDIRECT` settings can break reachable game paths. `ADD` normally propagates to callers; disabling propagation requires the entire caller chain. `ADVISE` describes instrumentation decisions, not current pass progress. Reentry and asynchronous save callbacks also constrain control behavior. [Official Asyncify guidance](https://emscripten.org/docs/porting/asyncify.html), [pinned settings](https://github.com/emscripten-core/emscripten/blob/6.0.8/src/settings.js).

The installed link policy adds `invoke_*` to suspension imports when indirects are retained, because the exception wrappers perform indirect calls. CDDA's actual source/SDL suspension paths and callback inventory are in the parent's `source-async-paths.json`. They provide no justification for excluding those callers wholesale. [Pinned link policy](https://github.com/emscripten-core/emscripten/blob/6.0.8/tools/link.py).

At Binaryen revision `89a81ef9b`, Asyncify checks `optimizeLevel > 0`. In the current `-Os` invocation it runs flatten/DCE, local simplification/coalescing, then default function optimization before and again after local save/restore insertion. Consequently, the expensive work could be ordinary size optimization, Asyncify transformation, or its nested optimizers. The active pass remains unknown. [Exact Asyncify implementation](https://github.com/WebAssembly/binaryen/blob/89a81ef9b/src/passes/Asyncify.cpp).

Two upstream reports prevent assuming that hours are normal: [#8927](https://github.com/WebAssembly/binaryen/issues/8927) describes continuous CPU and apparent Asyncify nontermination on Binaryen130/Emscripten6.0.2; it is closed, with no visible resolution in the retrieved page. [#7319](https://github.com/WebAssembly/binaryen/issues/7319) reports another module taking 5.34s at `-O2`, 806s at `-Os`, and 804s at `-Oz`. Different versions, modules, features, and platforms prevent identifying either as CDDA's cause or predicting an improvement.

## Recoverable candidate; not executed

For an independent output directory, retain every current object, source, dependency, and functional link setting; change the **Emscripten link argument** `-Os` to `-O1`. Keep `-sASYNCIFY`, all imports, indirect-call handling, exception support, filesystem/IDBFS, Embind, memory/stack settings, and SDL flags. Do not mutate or overwrite the current output. This requires no new compiler pass on the 438 existing native WASM object files.

The Emscripten policy runs ordinary Binaryen optimization only when `OPT_LEVEL >= 2`; Asyncify is added independently. Thus Emscripten link `-O1` produces an Asyncify invocation without a Binaryen `-O*` argument, avoiding ordinary size optimization and Asyncify's gated nested optimizers. This retains the conservative suspension graph. **Direct `wasm-opt -O1` has different behavior**: it sets Binaryen optimize level1 and still enables nested Asyncify optimization. [Pinned Emscripten policy](https://github.com/emscripten-core/emscripten/blob/6.0.8/tools/link.py), [exact Binaryen CLI](https://github.com/WebAssembly/binaryen/blob/89a81ef9b/src/tools/optimization-options.h).
