# Original input-context connection slice

Status: **source and exact-byte preparation passed; native execution not yet run**.
The original C++ gameplay remains authoritative. Rust presentation, platform and
input layers can consume owned observations; helper command authorization remains
Denied(UntrackedNativeReaders).

This fresh folder does not change the pristine upstream, frozen integration
proofs, full reference engine, current browser candidate, runtime package,
parent-owned v5 artwork, or shared Git state.

The proposed three-stage reservation executes twenty selected byte-exact original
member definitions using unchanged official class headers, plus the previously
compiled snapshot object. It is a bounded original-class executable, rather than
the complete original translation unit or a replacement input_context class.
The snapshot reader callbacks are the actual existing callbacks inserted inside
the original handle_input(int) member. They read real original class fields and
input_manager::action_contexts. Their prior synthetic-descriptor fixture is a
separate historical proof.

## Source and platform boundary

The original source is CleverRaven/Cataclysm-DDA 0.I-1, commit
7b2efa5cea38e4d4d97dd0e63b28b9148623da59, CC BY-SA 3.0. LICENSE-UPSTREAM.txt
is preserved. prepare-source.mjs verifies official Git blob identities for nine
source/header files, current accepted CPP2 pins, and the exact previously compiled
input-wait hook. SOURCE-SELECTION.json records the source range and exact
original/generated hashes for each selected definition.

The selected members include registration, native event resolution and default
insertion, both handle_input overloads, raw-event retrieval, timeout controls,
capability queries, default raw translation names and raw name equality.
Only handle_input(int) gains the previously accepted observation insertion.
All other selected bodies are exact upstream bytes. cata_utility.h supplies the
original value_ptr_equals template used by translation equality.

fixture-leaves.cpp deliberately supplies:

- Scripted input_manager::get_input_event, replacing SDL polling, timing, screen
  refresh, text/IME acquisition and event pumping. Injected events are not hardware
  acceptance and can differ from events SDL would allow.
- Scripted display_menu, creating a real nested original input_context and a
  deterministic binding edit. The original full keybindings UI is not linked.
- Controlled platform capability/gamepad queries and unexercised redraw/language
  leaves. The language action is automatically registered by the official class
  and explicitly unbound, so the null, unconstructed original game is not used.
- A harness-only original declared friend keybindings_ui to initialize original
  action tables. The original keybindings_ui definition is excluded, avoiding
  conflicting class definitions. There are no private/public macros or altered
  official class headers.

The exact original SDL set_timeout body writes original input_timeout and a
local inputdelay mirror. This tests its assignments, not actual SDL timeout
behavior. Capture checks compare all native context/action keys, user-created
flags, raw translation names and full binding records (including mouse/text/edit
fields) before and after observation. Translation caches, turn state, RNG, saves
and unrelated engine objects are not loaded and are not covered by this proof.

## Prepared genuine-WASM acceptance

Fifteen prepared cases exercise original registration order and duplicate
registration, local/default/missing observation, explicit local empty overrides,
legitimate native missing-entry insertion after observation, colliding keys,
unmatched mouse/ANY_INPUT/COORDINATE, normal timeout restoration, nested original
waits with current bindings, help timeout transitions, raw CJK usernames and edit
bytes, modifier matching, capability queries, exception unwinding, retained pins,
repeated observation and over-limit fail-closed contexts.

The twenty selected definitions are a compilation set; individual helpers run
when the cases use them. get_default_action_name's nonempty preexisting-name
branch and the full platform/UI implementation are not claimed covered.

Two original limitations are explicit:

1. Native get_action_attributes may insert a missing default action during
   input_to_action. The const observer must not do that before input polling.
2. An exception thrown by the input leaf does not restore the original manager
   timeout. The observer RAII scope still clears its own active state. During
   HELP_KEYBINDINGS, a nested return republishes the parent while the original
   help timeout is -1; normal outer restoration follows before scope exit.

Actual snapshot bytes are copied from the original native pin/data/size exports,
not reconstructed in JavaScript. The proposed run saves twenty-four exact raw
JSON records and requires fifteen independently named ordered checks, a fixed
native-record set and real linked artifact pins. Notifications are checked after
microtask delivery, but no real Asyncify/browser schedule is covered.

## Ownership and launch conditions

run-context-window.py adapts the accepted fixture thin owner. It loads the exact
CPP2 helper from its verified byte buffer and calls the unchanged load_guard and
run_owned primitives. Default invocation validates source/pins only; it does not
load the Windows guard or start a compiler, linker, WASM, Cargo or browser.

A separate root release is required for the sole owned heavy slot. The existing
7/9 GiB physical/exact-commit browser priority remains. Otherwise each stage
requires fresh 4/6 GiB, an aggregate 1 GiB kernel private cap, a sampled 1 GiB
working-set stop, 2/2 GiB global floors, one worker and 180 seconds. No threshold
is lowered, cache regenerated, downloader invoked or unrelated process stopped.
A failed/deferred attempt ends without automatic retry; fixed build outputs are
never replaced. The exact source plan is fixture-plan.json. Each native job,
root handle, native dependency, output and frozen SDK/input comparison must be
archived and independently reviewed.

Original direct readers still include wait_for_any_key, animation input,
debug prompts, pump_events/CheckMessages, ImGui button and SDL backend actions,
and raw curses prompts. A tracked parent can remain published while a direct
reader consumes events. This slice cannot authorize helper gameplay commands.
The frozen Rust consumer remains denied, and full browser/live-input, semantic
names, render/RNG/save and whole-game gates remain open.
