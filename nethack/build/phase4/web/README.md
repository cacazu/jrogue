# Official NetHack browser adapter

Changed 2026-10-02. This directory hosts the complete official NetHack 5.0.0 reference engine with Rust presentation, input and save validation. It is an intermediate localization phase: **画面操作は日本語、ゲーム本文は英語です。** Game prose has explicit untranslated events; the browser does not reconstruct semantic game IDs by matching completed English sentences.

`app.mjs` loads `engine/nethack.js` and `engine/nethack.wasm`, both built from the pinned official source and documented integration patches. The complete `nhdat` archive, including Lua dungeon/quest data, is embedded in the engine. `shim-host.mjs` adapts every official WASM shim callback; `dom-ui.mjs` renders immutable public windowport descriptors and accepts keyboard, mouse and touch. UI strings live in paired `en`/`ja` JSON namespaces in `browser-ui.json`, with Japanese selected by default. After engine initialization, formatting, key/direction mapping, completed Unicode text validation and save-envelope validation call the linked Rust C ABI.

Role, race, gender and alignment selection uses upstream `genl_player_setup`. Menus preserve original identifiers, accelerator/group keys, preselected flags, PICK_NONE/ONE/ANY modes and item counts. Long menus support filtering, paging, whole-menu and visible-page selection. Unrestricted key/direction prompts have a visible touch keypad and raw-key entry; arrow keys, eight movement directions and the upstream numeric/telephone/QWERTZ keypad options use the Rust input layer. Extended commands retain the exact upstream table index and normal-mode visibility flags. The original keyboard command set remains available.

New adventures use the official `!tutorial` option for the normal dungeon and starting inventory. The startup checkbox can select the original tutorial instead. These options enter libc through `nh_abi_setenv` before main, because the runtime may cache its environment before the JavaScript factory resolves. An explicitly supplied regression-test seed uses the same platform bridge; production supplies no fixed seed. Mobile scrolling follows the visible `MG_HERO` map descriptor when the hero moves out of view; this never reads hidden world state. Input diagnostics retain a bounded recent history and a separate total consumed count; they are not a replay journal.

Map rendering uses the original ASCII characters and colors. Status, menus, help/resource documents and message history use UTF-8 DOM nodes. Resize, locale changes and repaint read stored public descriptors without calling gameplay, RNG or input functions. No proprietary tile or audio assets are deployed.

## Saves

Saving is the original **S, save and quit** command and its original confirmation. The adapter captures completed files in `/save` at the final native exit, wraps the file bundle using the Rust source/ABI/checksum envelope, then waits for the IndexedDB transaction to complete. It waits beyond `exit_nhwindows`, because the core can write final scores after closing its windows. Resume creates a fresh module, validates the complete envelope, writes the original save files and enters the core's real restore path. Imported/downloaded saves are the same envelope; import rejects unsafe filenames, malformed payloads, wrong versions and failed integrity checks before modifying files or browser storage.

There is no serialization of a live Asyncify stack. A pending selection, More prompt, unfinished text draft or browser close is not a completed save. Finish the current interaction and save through the game. The save button is disabled for prompts and map-cursor selection. If IndexedDB fails after native exit, the validated in-memory save and auxiliary envelopes remain available for emergency download; a failed IndexedDB read blocks game startup rather than replacing existing data. Storage is scoped to the browser origin.

The native root `record`, `logfile`, `xlogfile` and committed bones are persisted separately from the completed adventure, but commit together in one IndexedDB transaction. Every new or restored adventure hydrates them before original main. The strict bones basename allowlist comes from the pinned `files.c` and `dungeon.lua`: `bonD0.5`, `bonM0.T`, `bonQVal.L` and the original optional single pool digit. This build has no compressed bones suffix or prefix directory. Temporary `.bn`, locks, live level files, DLB data and installer assets are excluded. The optional native `livelog` feature is disabled in this build and is not persisted. Native consumption/removal of bones is captured at the next native exit; closing the browser while playing cannot commit that change.

Downloads include both the completed save and persisted history. A download after death or quit can contain only history; importing it does not create a resumable adventure. Legacy game-only imports retain existing local history. All nested auxiliary identity, filenames and bytes are validated before storage or filesystem mutation. Restart/export controls stay disabled until final native persistence finishes.

## Verification and diagnostic surface

Local browser delivery uses the HTML files in this directory. From `nethack/`, run `node tools/serve-integration.mjs`, then open `http://127.0.0.1:3000/`. The current requested publication scope is local HTML and Node/browser verification; it does not include a new external Site deployment. Saves remain scoped to the local browser origin.

The phase 3 source adds source-issued native semantic envelopes, an additive Rust gameplay formatter and immutable nested public-name arguments. It never derives identifiers by matching displayed English. Complete quest paragraphs replace only the same contiguous original rows after every accepted source line and declared public argument is present. Missing/conflicting data, varying attributes/helper context and multi-line accessibility qualifiers retain the original English rows. Locale repaint uses the captured values; native history and completed save/auxiliary boundaries remain unchanged.

The frozen source-only checkpoint is `build/browser-semantic-source-verification.json`: **47 pure/mock checks and five syntax checks passed** with no WASM factory, browser, compiler or server invocation. The aligned compiled checkpoint is `build/browser-semantic-compiled-verification.json`: **67/67 passed**, comprising those 47 mock checks, six compiled platform regressions and 14 compiled semantic formatter/bridge boundary checks. Synthetic formatter envelopes establish Rust ABI behavior; they do not establish native producer association.

`build/browser-semantic-browser-verification.json` records **18/18 actual local Chrome checks passed** against WASM `edec818a…` and catalog `c79fe2a3…`. It verifies source-selected C message IDs, Japanese display and exact original English replay, all 13 roles, desktop/mobile input, 100 locale/repaint cycles with unchanged native world/state/RNG/input, native completed save/fresh restore, and score/log persistence. Every run binds ten exact runtime hashes. The browser disclosure remains because this is partial localization; this normal-adventure suite does not establish exhaustive quest, name, accessibility or campaign coverage. The initial failed harness-readiness attempt is preserved separately.

`build/browser-semantic-name-verification.json` adds **10/10 actual native naming checks passed**. A test-only original `-X` adventure uses the core's wishing, apply and quaff commands. Applying a lock pick toward an already visible creature captures the native nested monster-name event and replays its exact English source. An unknown crystal ball retains only its observed `the glass orb` literal, and a hallucinated creature retains the core's selected fantasy name without exposing a true-species ID. Two further sets of 100 locale/repaint cycles leave native state, world, RNG and consumed input unchanged. The producer tests never write gameplay fields or invoke an extra native name generator.

Actual quest producer and typed accessibility-prefix acceptance remain pending. The original `-D` authorization requires a valid libc passwd lookup; the installed Emscripten `getpwnam`/`getpwuid` stubs always return NULL. Both the original rejected startup and an approved isolated MEMFS identity attempt are preserved in `build/browser-semantic-debug-identity-blocker.json` and the referenced failure reports. No host account, original wizard policy, UID or native mode flag was changed. The compiled formatter and pure grouping tests cover quest/a11y boundaries, but that is separate from native campaign delivery. Original `the(xname(...))` object article transforms currently retain their exact observed literal instead of a nested name event.

The serial verifier is `node --max-old-space-size=128 tests/browser-host-semantic-compiled-verify.mjs`; real browser acceptance uses `tests/browser-host-semantic-browser.mjs` and `tests/browser-host-semantic-native-name-producers.mjs`. Resource reports are `build/browser-semantic-compiled-memory.json`, `build/browser-semantic-browser-memory.json` and `build/browser-semantic-name-memory.json`. They record a Windows Job Object peak and confirm that each owned process tree is closed after its finite run. Browser profiles stay under `build/browser-profiles/`, and at most one game module/page is live at a time.

Historical phase 2 verification is `build/browser-boundary-verification.json`; its runner was `node tests/browser-host-verify.mjs`. The 23 focused host checks audit the callback inventory against preserved official source, menu union byte ownership/counts, UTF-8 boundaries, positional input, numeric questions, command indices, status masks, source-tagged save/auxiliary payloads, final-exit timing, the atomic storage boundary and 100 redraws with no consumed input. Six additional checks call the actual compiled Rust/C ABI, including portable auxiliary envelopes and legacy import compatibility. Those historical hashes and results describe the tested English reference bundle, not the new phase 3 pipeline. They do not establish complete Japanese prose coverage.

`window.netHackTest` exposes the module, current host/phase, input wait type, immutable frame, consumed input count, callback trace, locale repaint and committed-file import/export for real-browser checks. `diagnostics.finalized` marks completion of final native exit and the persistence attempt; `storagePending` records a failed durable commit with an emergency envelope still in memory. The engine exports read-only state/world/RNG checksum helpers separately. This diagnostic surface is not a snapshot/restore implementation.
