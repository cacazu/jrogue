Added 2026-10-02. Source-owned presentation persistence plan; implementation and runtime verification remain incomplete. Full Japanese save/load and accepted message/history provenance are already within the parent's authorized local game task.

Original NetHack save files, journal nodes, flags, linked lists, message history and native English bytes remain unchanged. A versioned platform sidecar lives beside the browser's existing save envelope. It is bound to the exact engine/source ABI, catalog schema and a digest of the complete native save payload. No data is imported when that binding fails. Typed event validation, recursive bounds, UTF-8 checks and all public-visibility rules also apply on import; a user-modified or missing sidecar leaves exact native English.

The platform records semantic envelopes only synchronously inside an original accepted callback, when the existing getter is eligible. It never calls a new getter during saving or repaint, walks hidden C journal nodes from JS, or manufactures events for queued/rejected messages. Locale changes render those immutable already-public records. Ordinary retained messages and original message-history rows can therefore persist their certified event plus exact public English row as part of the existing accepted-record model.

Deferred chronicle records need a native public-view ticket. The original major/spoiler predicates run once and retain their exact decisions. Only after those predicates accept a row does the native display loop advance a presentation-only **accepted row ordinal**, bind the actual window/view ticket and expose the existing certified event. The ticket identifies the public view; it contains no hidden-node allocation ordinal, pointer, flags, node count or private gaps. The browser commits only a complete ordered vector of accepted callbacks from that view, with each event and its original public line. A partially observed view remains unsuitable for native restoration.

After a fresh engine restores its unchanged C save, the sidecar's accepted vector can be supplied as bounded platform data. The original display loop again runs all original filters first. At each accepted leaf, an import candidate is selected by its source-owned view ticket and accepted public ordinal, then checked against the exact already-rendered public line and original already-public turn. This byte comparison only rejects an overwrite/mismatched saved record; it does not select an ID or translation by English content. A different final/wizard view contract, new intervening row, missing position, unknown event schema, clipped line or incomplete vector rejects that view and keeps English. No hidden entry is exported to reconcile it.

Native log sidecars from the current session remain bound directly to their original allocated nodes and supersede imported candidates. Imported candidates attach only at the accepted leaf; they never mutate native journal structs, persist gameplay flags, or alter the native saved text. Every native node free/replacement invalidates any transient association before memory reuse. Source-private ownership and platform accepted-record storage are distinct lifetimes.

Lua config errors need their own exact creator-to-delivery record contract. Capture the source-owned record when the original `config_error_errmsg` is allocated, invalidate on its original free, and expose it only if the original Lua/UI delivery makes that specific record public. The current proposal intentionally supplies no semantic getter for the queued list. Its qualifying prefix, line and punctuation must be source-selected at the actual original delivery; no later hidden-state query is allowed.

Required verification is fresh-instance native save/load with exact native payload hashes; Japanese and English replay of previously accepted history; missing/tampered/version-mismatched sidecar fallback; no hidden/spoiler-filtered rows or count leakage; original filters/callback order and node address-reuse checks; locale/repaint invariance of native state, RNG and input counts. These tests run only in the parent's separately released serial build/browser slots. Until then, restored deferred records remain an explicit incomplete coverage gate.
