Added 2026-10-02. These integration sources use the NGPL and preserve all original NetHack notices. This directory contains separate source proposals; no proposal here has been applied, compiled, linked or exercised in a native/browser runtime.

`prepare.py` generates original static-call wrappers, source operations, a private bridge extension and six reversible native definition transformations. `test_prepare.py` verifies 19 source contracts. Run both with the existing SDK Python; neither command invokes a compiler.

There are 427 distinct literal source IDs at 434 native call sites. Seven precision-bound IDs call the original API without constructing an event, leaving 420 event-eligible IDs at 427 sites. The 37 dynamic, declaration or null-origin candidates remain original English. These are lexical source counts: a conditional source branch and a file-only dump are not proven browser callbacks. The catalog contains English source frames and ten native context recipes; its Japanese map is deliberately empty until the parent's reviewed frames are merged. Source preparation is not completed Japanese or runtime coverage.

The original call layout is preserved, including commas, comments, whitespace, preprocessing lines and argument evaluation. Every source expression is evaluated once; original argument order remains C's unspecified order. Text capture has name permissions zero, so raw fields cannot borrow an earlier pooled pointer's name descriptor. Any source-approved name or selected-literal extension must provide its own original producer contract. Unconsumed arguments and precision-bound text cannot cross the public event boundary.

The existing synchronous getter remains `nh_abi_semantic_event(callback, window)`. There is no new exported ABI in this proposal. Native definition hooks claim only a pending scope whose kind and API match the original entry. A missing, invalid, exhausted or truncated scope keeps the complete native English output.

| `panic` / `panic1` | Only the final original `raw_print(buf)` after original formatting. Earlier shutdown instructions retain their own source frames. The original panic counter, recovery, logging, abort and terminal control flow remain intact. A possible `BUFSZ-1` clip rejects the event. |

Only the original `show_gamelog` `putstr` after major/spoiler filters exposes it. Original journal text, flags, file logging, save bytes and tab substitution stay untouched. |
| `dump_forward_putstr` | Only the original `!no_forward` forwarding branch. File-only dump writes publish no event and receive no extra UI rows. |
| `exit_nhwindows` | Exact original `shim_exit_nhwindows/-1` callback with matching API. Original final scores, file writes and terminal exit sequencing remain authoritative. |

Journal sidecars own copied UTF-8 original text and typed event JSON. They are bounded to 4096 records and 8 MiB total. Every original node free first invalidates its record; raw/restored allocation also forgets a reused address. Monotonic presentation generations and exact original-record byte integrity are rejection checks, not English translation lookup. No name, knowledge, visibility, predicate, RNG, command or renderer is queried. Records without certified provenance remain English.

Future composition must use exact source-operation metadata to identify Phase4's two renamed internal config `pline` leaves, then apply `config_operations` with those actual aliases. The generated caller operation ledger and definition patch are separate; this directory is not a build-ready joint Phase6 pipeline. Do not apply them by matching rendered messages or indiscriminately overriding source names.

`persistence-plan.md` describes a scoped, already-authorized accepted-public-event sidecar for message/history restoration. It preserves native save bytes and does not export hidden journal/config records before original acceptance. It is a concrete next integration task, not an approval blocker. This proposal does not implement or claim that restoration yet.
