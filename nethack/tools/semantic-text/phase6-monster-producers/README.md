# Isolated monster producer preparation

This directory contains an uncompiled proposal for public monster-name composition. It extends source-selected `x_monnam` output and six capitalization wrappers while preserving the original C gameplay. No runtime, canonical catalog, shared ABI, compiler, browser, Git or Site changes were made. Every runtime approval remains false.

Run finite preparation and source checks from the repository workspace:

```powershell
C:\Users\kit\emsdk\python\3.13.3_64bit\python.exe -X utf8 nethack/tools/semantic-text/phase6-monster-producers/prepare.py
C:\Users\kit\emsdk\python\3.13.3_64bit\python.exe -X utf8 nethack/tools/semantic-text/phase6-monster-producers/verify-source.py
```

The generator can read a previously composed `do_name.c` with `--source PATH`. It requires the existing original `nextmbuf` invalidator and replaces only the narrower stock ordinary-name observer. All outputs stay under this assigned directory. There is no apply/build/runtime entry point.

The fixture composes the existing stock name transform, the Phase5 generation/snapshot bridge, and this new extension. Future integration must append the Phase6 object/helper/monster extensions to one Phase5 bridge, retain the existing monster/object label headers, install the paired fragment, and enable name capture only for the exact original name-producing argument contracts. The isolated fixture is not the full Phase4/Phase5 application tree.

## Public facts and ownership

The original public species pointer is cached at the original `pm_name` selection expression. `do_mappear` uses the already-selected apparent monster, including the original gender-sensitive `pmname` result. Observers add no second `mappearance`, `Mgender`, `mon_pmname`, `canspotmon`, field, naming or RNG query. The bridge itself has no target monster/state access. Existing pointer identity against the selected source table identifies labels; byte comparison only rejects stale or clipped output.

The original source appends select invisibility and saddle facts. The final native article switch selects ownership: `ARTICLE_YOUR` renders `あなたの`; English `a/an/the` has no Japanese inflection. The complete original English is a retained argument, so EN replay uses its exact native wording. The outer JP recipe uses only the original selected pieces and does not invent gender, attitude, species, owner, rank or deity.

An adjective requires a copied, exact source-issued semantic descriptor. A non-null empty adjective remains distinct from null and currently falls back. Reading an input string does not authorize a new descriptive translation or a persistent binding for pooled static literals. Prefix capture is private until the corresponding actual native append and complete final-output proof succeed.

Pure user names may remain literal only after their original construction certifies that provenance. `MGIVENNAME` can also contain generated mplayer titles. The native title-splitting branch is unsupported. Both the earlier `called` consumer and the ordinary personal-name consumer require a descriptor for their exact original name pointer; they do not locally certify arbitrary field text. Without creator provenance, the complete original name stays English. A future creator can provide a literal proper-name event or a composite with the original selected rank descriptor. A later `is_mplayer`, rank query, renderer parser or English reverse lookup is prohibited. The reserved proper-name observation helper has no current consumer call and grants no provenance by itself.

Such a future creator must also invalidate the original allocated name on replacement/free before its address can be reused; pointer-plus-byte equality cannot certify a reused heap address by itself. This proposal does not install that creation/free producer. A future priest descriptor must be caller-owned through its stack `pname`/`buf2` lifetime. This consumer deliberately avoids interpreting a coincidental registry match at a reused stack address as priest provenance.

`priestname` in `src/priest.c:302` can reveal or conceal the deity by original high-priest distance/endgame guards and can select a hallucinated public deity. `rank_of` in `src/botl.c:332` selects role/rank/gender privately. No added observer reconstructs either from real fields. `shkname` in `src/shknam.c:856` temporarily clears/restores `isshk`, can name through `noit_mon_nam`, and can select a different proper name under actual Hallucination; those original operations remain untouched. Source output snapshots preserve the result actually produced.

## Memory and failure behavior

The stack owner copies adjective and body event JSON, English prefix/body bytes, and selected public pieces before they can be overwritten. A ghost captures the single original suffix return; each shopkeeper call captures its return at the original evaluation point. The original C unspecified argument ordering remains unspecified. No helper repeats the original naming/RNG expression.

The proposal uses the Phase5 pointer/generation/byte-guard registry: 32 slots, 4096-byte JSON, `BUFSZ` including NUL for public text, and `uint64_t` generation overflow rejection. The original `nextmbuf` invalidator remains. `rndmonnam` invalidates its original static output range before any original display RNG call, so a later bogus-file result cannot inherit an earlier real-species event. Case/copy propagation copies the event before invalidation. Registration clears the destination before every failed final/copy observation.

Prefix, body and final article are reconstructed from the captured original pieces only to prove that the complete native English was retained. Missing, ambiguous, overwritten, nonterminated, clipped, oversized, invalid-JSON or formatter-depth failures produce the whole native English. No partial Japanese name is installed. The approximately 9 KiB stack owner and nested call stack have not been measured by a C compiler/runtime. UTF-8 and the existing Rust depth/expansion/format limits still require actual pipeline acceptance.
