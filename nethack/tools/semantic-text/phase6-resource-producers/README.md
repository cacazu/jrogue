# Source selected resources

This directory prepares an isolated source proposal. It has not been compiled,
applied to `work`, or connected to a browser. `prepare.py` reads the pinned
official source, frozen authoring queues, authored fragments, and an existing
generated data snapshot. `check.py --report` checks those source contracts.

The current snapshot has 14 certified data members and 3,236 native byte read
intervals. The generator reconstructs the entire rumors/random/oracle data from
the original source order, original padding/encryption recipes, and original
numeric headers. It compares all reconstructed bytes to the actual generated
files and the member ranges in the actual DLB archive. These are build-time
integrity checks, never a runtime lookup of English text.

The C proposal remains disabled until the platform hashes the actually loaded,
immutable archive and supplies its real SHA-256. Supplying a hard-coded expected
hash is invalid. Original selected archive offsets and member sizes must also
match. Reopening a changed resource or changing the data mount requires
invalidation and fresh certification. External stdio files and other DLB
backends have no inferred identity.

`generated/source-observers.patch` adds observers to five original files. It
preserves every original C expression and native call. The checker unwraps the
observers to recover each original file exactly. Prominent modification dates
and original copyright/license headers remain in the proposed files. No shared
root, active/default sources, frozen catalog, or authoring queue is changed.

The DLBLIB observer takes the original `dp->mark` before a read and after the
original read. It does not call `ftell`, read a file again, or repeat a selection.
A partial read, unknown member, wrong interval, or capacity failure yields the
original English. Handle slots own live IO provenance; there is no registry
mapping text pointers to identities.

`get_rnd_line` records only the source row actually selected by the original RNG
and native reading loop. `getrumor` observes its original executed marker-removal
branch. The seventeen private `[cookie] ` authoring origins produce public IDs
derived from the text after removal. Neither truth buckets, selection predicates,
nor marker-bearing IDs/templates enter player events. If the original exceptional
path retains a marker, its exact native output remains the fallback. `outrumor`
copies the descriptor by value and scopes it around the original `pline1` or
`verbalize1` call; quoted variants retain the original quotation semantics.

The same selected-row capture covers original epitaph/engraving/bogus-monster
selection. Bogus-monster prefix removal is observed in its original branch.
There are no new name, gender, visibility, hallucination, knowledge, or RNG
queries. The caller must copy the selected descriptor immediately through its
specific original producer. Random engraving damage, subsequent mutation,
custom names, and save/load/bones still require an explicit persistent sidecar;
the native spelling and damaged text remain literal until that lifecycle exists.

The oracle proposal accepts only a complete original window owner, every row in
the original order, and the original delimiter read. It offers a whole paragraph
descriptor at the original display boundary. The host must retain all native
rows and adopt a group atomically; missing provenance means the whole English
paragraph. Its group getter is an additive proposed API and has no current
host/Rust integration. The special oracle's cited third-party excerpt has no
Japanese translation approval.

`whatdoes_help` receives a template variant preserving its original leading
whitespace removal and surviving newline. The tty proposal preserves newline
removal, and tabbed rows remain unbound until a Unicode column contract is
reviewed. The actual shim browser `display_file` path reads with
`nh_abi_readfile`, then splits UTF-8 at CRLF/LF. It requires a certified complete
asset and original byte offsets before associating these source units. A
filename and a rendered string are insufficient. No host file is edited here.

`lua-source-producer.plan.json` records exact executed-call candidates, literal
token positions, and source hashes for the 59 Lua public source sites. It is not
an executed Lua call-owner proof. The native loader must certify the actual
chunk, then bind the original source/PC/field owner. A debug line alone is
insufficient for a moved table or dynamic value. Accumulated `des.message`
text needs the complete original append sequence and already captured original
quest substitutions, including `%d`; it must never call `convert_arg` again.
Persistent Lua object/monster names, engravings and graves need original creation
ownership, mutation lineage and versioned safe persistence. `Elbereth` stays
unchanged in native gameplay data.

`public-label-producer.plan.json` retains all 665 original selected table token
sites. The native caller must carry its already selected row, subfield and index
once into a copied typed label descriptor. Rank selection, role copies, pronouns,
deity prefixes, option/command parser identities, status cell widths and UTF-8
precision are explicit contracts. These producer bindings remain unimplemented.

The source catalog has 8,257 English keys and 8,254 authored Japanese keys in
this snapshot, including original resource units and consumer/quoted variants.
They are source proposals, not runtime Japanese coverage. Three native default
entries keep explicit English fallback. The 1,076 encyclopedia/tribute units
with unresolved excerpt-specific translation rights remain outside this
catalog, with original notices and English assets retained.

Existing Windows-generated `oracles` has 140 CRLF records and `rumors` has 789.
Original `outoracle` recognizes `---\n`; original DLB CR normalization is guarded
by `MSDOS`/`WIN32`. The target macro and original consumer behavior must be
verified before applying this snapshot. Target data regeneration must rerun the
original makedefs recipes and recalculate all offsets; a newline replacement
afterward would invalidate the native numeric offsets and these certificates.

Commands from the project root, using the configured Python executable:

```text
python tools/semantic-text/phase6-resource-producers/prepare.py
python tools/semantic-text/phase6-resource-producers/check.py --report
```

No command here runs a compiler, native game, Node, or browser.

25 files covering the catalog, C proposals and bridge, private metadata,

All 400 author entries retain their original English, IDs, source records, and
argument unions. The three reviewed Japanese base refinements also update their
three existing quoted variants. Two complete 23-file generations are identical,
and both source checks pass 54,473 assertions with zero errors. Proposed C,
native offsets, archive certificates, and ownership plans remain byte-identical.
`check-refresh.py` verifies the preserved history and final content diff.

These certificates still describe the old Phase4 CRLF snapshot. The actual
original-consumer gate established that snapshot's target incompatibility.
Newly generated target LF data needs fresh member/archive hashes, read intervals,
offset certificates, and native consumer/ownership validation before any wiring.
This refresh adds no runtime-approved IDs and does not alter the frozen composer,
engine, Rust, browser assets, or publication status.
