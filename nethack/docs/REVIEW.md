## Boundaries checked

- `TextId` validates stable ASCII English keys. Typed events reject unknown fields. Templates reject mismatched/missing/extra arguments, invalid braces, oversized text, and parameterized name references. Japanese fallback is a separate diagnostic value.
- The browser renders text through `textContent`, not HTML parsing. Menu/name strings and glyph descriptors are consumed from the official windowport; extended commands hide the upstream wizard/unavailable/internal flags. No new hidden-state-name lookup was found in DOM rendering.
- Rust input/presentation/save-envelope functions do not call gameplay exports or RNG. Browser resize, redraw, and language changes reuse windowport observations. These code-level properties still require state/RNG checksum checks against the real engine.
- Rust save envelopes bind source commit, release, ABI, schema, encoding, length, and CRC32. Unknown fields and malformed/noncanonical hex are rejected before output. CRC32 is accidental-corruption detection, not authentication.
- The FFI documents borrowed, nonoverlapping, valid buffers; null/size bounds are checked. Undersized output writes nothing, and invalid save validation returns before output. A fabricated nonnull pointer remains caller error, as documented.
- Browser import validates the envelope and all filenames before writing files, rejects path traversal/duplicates, and requires an empty save directory. It does not serialize the live Asyncify stack.

## Remaining checks for the release owner

1. Run real-browser desktop/mobile checks for the fixed findings, including storage error injection, count validation, default menu confirmation, and number-pad directions.
2. Inspect the final downloadable source archive, license links, changed-file/date notices, pinned Lua copyright/license, Rust dependency notices, and reproducible build inputs. A private Site still distributes executable code to recipients.
3. Align/document the effective save limit: JS permits 16 MiB of decoded files per save/auxiliary set, but those files are first base64-encoded into JSON and then passed through Rust's 16 MiB opaque-payload bound. Effective raw capacity is approximately 12 MiB minus metadata; a portable export combines both sets under that same payload bound. Large valid native files therefore fail below the JS validator's raw-file bound. Typical saves are much smaller; test the actual boundary if a maximum size is promised.
4. Input diagnostics are now bounded and total consumption is tracked separately. Independent long-adventure regression passed. Keep diagnostics separate from saved gameplay state.

## Auxiliary persistence and runtime notices

The final auxiliary implementation was reviewed statically against the pinned source and actual compiled macro configuration; details are in `docs/AUXILIARY-PERSISTENCE-AUDIT.md`. Its anchored root-file allowlist matches the native record/logfile/xlogfile and committed bones grammar. It excludes transient `.bn` files, ongoing level/lock files, data, disabled live logs, and other branches without possible bones. Hydration validates before mutation and replaces the complete allowed snapshot, retaining deletion of consumed bones. Native `onExit` captures after score writes, and the host reports exit only after persistence finalizes. Completed saves and auxiliary envelopes share one awaited IndexedDB transaction. Complete pending state is retained before a failed storage commit; legacy game-only imports retain existing history. No new implementation blocker was found in this static review. Real native score/bones lifecycle and browser storage-failure evidence remain the integration owner's responsibility.
