# Semantic text integration audit

This is an independent, read-only source and design review of Phase 3. Official NetHack 5.0.0 remains the gameplay engine; Rust owns text presentation and input/platform contracts. The reviewed design can attach source-selected IDs and typed arguments without replacing gameplay or reverse-matching rendered English. Acceptance still requires compiled and browser evidence for the new instrumentation. The earlier 17/17 browser result belongs to WASM `298ae4f9e6c81695cdee9c2d7c410961215092cd877a64b4bcc9c671eb0ee55d` and does not verify Phase 3.

Review scope: original `upstream/NetHack-5.0.0/src/pline.c`, `src/windows.c`, `src/cmd.c`, `include/winprocs.h`; seed metadata; current `tools/semantic-text/nh-semantic.{c,h}`; Rust domain/presentation/FFI; browser capture/presentation code. Sources were read without compiling, launching a browser, modifying gameplay, or changing adjacent projects. Line references below are to the pristine upstream files unless a different path is named. The Rust review used the installed Rust skill.

## Coverage being integrated

The exact `locales/source-seed.metadata.json` reviewed has SHA-256 `adc0fc9df7846bda31f231eead00aad1ebb2172ce544e60b059d3a666b67acc0` and 524,349 bytes. Its 483 IDs reference 492 source call sites: 415 entries have no arguments and 68 are formatted. There are 75 conversion occurrences: 71 `%s`, two `%c`, and two `%i`. The two `%c` cases are `Yuck%c` and `Yum%c` in `src/eat.c`; their existing expression chooses `!` or `.`. The `%i` case is `[HP %i, %i left]` in `src/hack.c`.

205 entries use direct templates; 278 require a complete semantic message with helper context. 65 entries explicitly require further localization of argument values. Copying their already visible English strings is a safe partial implementation, but does not complete Japanese entity/action text. The seed and translation-status files still declare runtime integration false and zero localized runtime messages at this review checkpoint. That declaration must be changed only after actual instrumentation and verified delivery, with precise counts and fallback dispositions.

311 existing IDs have a final ten-hex-character digest starting with a digit. Preserve these IDs. The additive validator change accepts a terminal exact ten-hex segment while keeping preceding semantic name segments constrained. Rust/JS/catalog validation needs agreement and tests; silently renaming IDs would break source provenance. The C bridge accepts a broader ASCII syntax, so it should be treated as transporting generated descriptors rather than accepting arbitrary external IDs.

## Native behavior that must remain authoritative

| Source | Existing behavior | Integration requirement |
| --- | --- | --- |
| `pline.c:65–81` | `putmesg` selects urgent/no-history attributes, calls `putstr`, then `SoundSpeak` | Attach metadata to the actual text callback; preserve English for sound and flags |
| `pline.c:161–190` | Accessibility consumes the selected location, calls `coord_desc`, and recursively emits `dirstr + ": " + line` | Carry the already computed public qualifier once; preserve it visibly or use the exact native-English fallback |
| `pline.c:194–224` | Native printf formatting, special exact `%s` path, size check and truncation | Do not reinterpret literal arguments or replace native formatting; disable semantic rendering if native truncation cannot be reproduced |
| `pline.c:233–263` | Dump log precedes filtering; recursion may use raw output; message type, sound and Norep filtering use English | Keep this ordering and English inputs; do not display semantic events for suppressed messages |
| `pline.c:266–284` | Vision recalculation may emit nested messages; then screen flush, accepted message, external handler, previous-message update and STOP behavior | Expose an event owner only around the accepted callback, never around the whole native pipeline |
| `windows.c:1785–1812` | `add_menu` colors rows from the English text before the window callback | Claim the row owner before native work and bracket only `win_add_menu`; retain all selectors, identifiers, flags and colors |
| `cmd.c:5471–5582` | Query truncation, canned/fuzzer responses, optional menu prompt, native question, queue/log handling | Attach only to the actual displayed question or alternative menu title; preserve responses/default/input state and do not tag response echoes |

`SUPPRESS_HISTORY` excludes native dump history and, when supported by the port, becomes `ATR_NOHISTORY`. Browser visible transient messages and selectable history must honor that attribute. The current host keeps the original source English separately for core `getmsghistory`/save history and keeps semantic UI records independently. Native restore of an English-only history line must remain an explicit English fallback; reconstructing an ID from that saved line is prohibited. A future semantic history sidecar needs versioning, source pinning and a native-history association protocol.

Helper branch precedence is part of message meaning. `You_feel` chooses dream while Unaware (`pline.c:388–400`). `You_hear` returns without emitting for `(Deaf && !Unaware) || !acoustics`, then chooses Underwater before Unaware (`436–452`). `You_see` chooses Unaware before Blind (`455–469`). `verbalize` adds quotation marks and its native flag; callers already decide audibility (`476–489`). Japanese templates must render the complete selected sentence with those distinctions. Generic English-prefix concatenation can duplicate Japanese predicates or silently lose dream/sense meaning. Missing or unreviewed variants need the exact original visible English, not a translated base sentence with a missing qualifier.

## Minimal observation ABI and ownership

The approved getter is read-only:

```text
nh_abi_semantic_event(callbackName, window) -> UTF-8 JSON or null
{
  "event": {"id": "source.selected.id.0123456789", "args": {
    "arg_1": {"type": "integer", "value": 33}
  }},
  "context": {"api": "You_feel", "helperVariant": "dream",
              "locationPrefix": "already computed public qualifier"}
}
```

`locationPrefix` is optional and contains the original `dirstr` without the native following colon. The no-window sentinel is `-1`. `event` and `context` stay separate; the existing strict `TextEvent` schema must not receive unexplained outer fields. Helper variants are a closed set (`plain`, `dream`, `underwater`, `blind`, `quoted`). Context is captured from the original execution; neither Rust rendering nor locale changes read live player flags.

The per-call-site wrapper should replace only the original API token, keep every original argument expression in that call, evaluate each once, snapshot already public strings into owned memory, and invoke the exact original API using those captured values. Name producers such as `xname` and `mon_nam` can choose descriptions or use shared buffers; replaying them from rendering would be incorrect and could consume RNG. C argument evaluation order remains unspecified: retaining the argument expressions does not by itself prove identical compiler ordering. Calls with multiple stateful name/RNG arguments need deterministic differential evidence or an explicit unsupported disposition.

The engine owner proposes explicit logical-emission claims: `vpline` claims the pending MESSAGE scope at entry; unwrapped nested `vpline` receives no owner; only accessibility recursion forwards that owner once. `putstr`/raw output are bracketed only at their accepted native emission. Menu rows and questions similarly claim before native work and expose the owner only at their actual callback. This solves the concrete defect in a weaker scheme where a pending outer message could incorrectly tag an unwrapped message from `vision_recalc`. Callback-name/window matching alone is insufficient.

Current bridge scopes own copied arguments and serialized metadata on the heap, nest through a parent chain, and remove forwarded/emission references at scope end. This is compatible with Asyncify only if that exact scope survives suspension and its pointer is never exposed after cleanup. The browser must synchronously read, validate and copy the envelope before its first asynchronous wait. UI descriptors must be immutable; later native buffer reuse, WASM memory growth and locale repaint cannot change them. Any output view must use the current WASM memory view after an allocation/growth.

Invalid UTF-8, allocation failure, unsupported formatting, absent catalog/variant/export or malformed metadata should disable that observation and retain native English. These failures must not skip a native call, change a response, or abort otherwise valid gameplay. Bounds need to apply to the whole envelope, including escaping and context. The current additive Rust formatter and C bridge both use a 256 KiB envelope/JSON limit, with at most 64 arguments, 64 KiB literal text and 128 KiB rendered output. Legacy direct-event FFI retains its earlier 64 KiB bound. Limit/OOM boundary behavior still needs verification.

## Formatting and public knowledge

Generated templates can use canonical named placeholders such as `{arg_1:%c}` while preserving the original printf conversion in metadata. `%c` takes a promoted integer and produces the C byte character: 33 becomes `!`, 46 becomes `.`, not their decimal spelling. Current seeded integers are C32 values; the bridge statically asserts 32-bit `int`/`long` and validates their range. Rust may retain the larger i64/u64 types for other adapters without expanding the native transport claim.

The additive Rust source now parses signed/unsigned integer conversions, flags, constant/dynamic width and precision, length modifiers and character/text conversions. Those capabilities exceed the current seed; their existence is not evidence of native capture coverage. Dynamic `*` width and precision consume separate promoted integer arguments; metadata and wrappers must bind them explicitly. Negative width means left alignment, negative precision means omitted precision, and integer zero/alternate prefixes and signed minima need exact tests. `%n`, floating types and other unmodeled cases require an explicit unsupported/fallback disposition. Byte-oriented `%s` precision over multibyte text must have a documented UTF-8 policy rather than claiming general C-byte parity.

Literal user names, wishes, fruit and labels remain literal UTF-8 arguments even when they contain `%`, braces, quotes or newlines. No argument may expose an object pointer, true unidentified object type, hidden monster identity, undiscovered appearance mapping or a private gameplay field merely to support translation. A future `text_id` argument must describe the public identity/appearance already selected by the original producer. It must not recover identity from the finished English or reread hidden objects on repaint. Current copied English entity strings leave partial English in Japanese sentences and must be counted as such.

Current `app.mjs` uses ordinary `JSON.parse` for native envelopes; C32 values are exact in JavaScript. The host rejects inexact Number arguments, and programmatic BigInt events serialize exact i64/u64 values. Expanding native JSON beyond safe integers requires a lossless decoder or a separately specified decimal-string transport. Converting an already rounded Number to BigInt would not recover its value.

The Rust gameplay renderer now retains `locationPrefix` through a catalog context rule and explicitly marks raw qualifiers as Japanese fallback. If that rule is absent, the browser catch path retains `sourceText`. Preserve this behavior: translating the body while discarding the native accessibility direction would lose information. Future localization of that direction must capture structured public coordinates/direction at the same source decision, without calling `coord_desc` a second time.

## Required verification before claiming runtime integration

1. Reconcile every generated wrapper against the exact seed source location/API/format/argument list; count enabled, excluded, unresolved and compiled sites. Compare original English output and native side effects for all captured calls, including helper variants and native truncation.
2. Exercise Norep, MSGTYPE_NOSHOW, urgent messages, no-history, early raw fallback, nested unwrapped messages during vision recalculation, nested wrapped messages, a11y recursive forwarding and external handler/sound paths. Assert one correct envelope per actual logical emission and no stale ownership.
3. Force a real Asyncify question/menu wait, grow or reuse native memory, repaint/change locale while pending, then answer. Verify frozen arguments/context, retained menu selection/text draft, original selector/default/response bytes and input counts.
4. Test `%c` `!`/`.`, both HP integers, literal percent/braces and UTF-8, absent/extra/wrong-type arguments, all 311 digest IDs, unsupported helper/format, missing exports/catalog entries, escaped envelope size limits and allocation failure. Future width/precision/length cases require native differential tests before enabling those producers.
5. Use an unidentified object, hallucinated name, blind/sensed message, sleeping/dream message and underwater hearing. Ensure the public description remains stable through repeated locale switches and that hidden identity is not added to the event, UI or diagnostics.
6. Repeat the verified reference engine/browser suite against the new artifact: all 13 roles, PC/mobile controls, menus/queries, native save/fresh restore, quit/score and auxiliary persistence. Verify original-English native history and honest fallback after restored history.
7. Run repeated render/locale changes with unchanged hero/world/RNG checksums and unchanged queued/consumed input. Compare seeded command traces with the uninstrumented reference. A source inventory or pure mock test cannot establish this gameplay invariant.

These are acceptance requirements, not tests executed by this review. Existing old-artifact 17/17 and boundary 29/29 evidence should remain pinned independently. Long campaigns, all quest/ending/death/bones paths and complete Japanese text coverage remain outside those results.

## Follow-up: quest producer contracts

`questpgr.c` uses a separate substitution language, not printf: `%c` means the player's role class, `%r` a rank, `%o` an artifact, and optional modifiers apply articles, capitalization, pronouns, plurals or possessives (`convert_arg:236–325`, `convert_line:328–419`). Source-selected quest IDs must be bound to the resolved section/message field and selected array element, not recovered from a rendered line. `com_pager_core:517–527` may resolve a fallback message key; `566–569` chooses an array entry using native `rn2` once. Record those actual selections without another random draw or locale-dependent selection.

**The raw quest text is also gameplay input.** `com_pager_core:543–547` returns unconverted English text without displaying it. `stinky_nemesis:172–189` inspects that text for English gas/fumes phrases to decide a gameplay effect. Keep the official Lua data and this raw-text path unchanged, and emit no UI observation from it. Replacing native quest resources with translated Lua would change mechanics.

Capture only substitutions already performed by the original visible conversion, including its selected pronoun/modifier result. Do not call `convert_arg`, `qtext_pronoun`, name functions or role/deity getters again during rendering; do not pre-export unrelated quest state. A copied native English substitution is a valid partial fallback. Japanese grammatical reordering needs source-token argument bindings and reviewed locale templates, without parsing the completed English.

`deliver_by_pline:423–435` and `deliver_by_window:439–455` split and convert native lines separately. English and Japanese source line breaks need not align. Repeating the full translated paragraph for each native line, translating only the first line, or suppressing accepted lines silently is incorrect. Define an explicit source-line/paragraph observation contract that preserves native filtering and history, or fall back for unsupported alignment. Automatic synopsis creation at `575–589` must remain native. Explicit/generated synopsis conversion at `597–608` calls `putmsghistory` directly and is history-only; it needs its own captured history observation or an explicit English fallback. Special-level text also uses `deliver_by_pline:654–662` and cannot inherit a quest ID without a separate source binding.

## Follow-up: visible name observation registry

The parent's proposed bounded pointer-plus-generation registry can bind an original returned public name buffer to a nested semantic descriptor without reverse lookup of English. Invalidate before every original `nextmbuf`/`nextobuf` reuse, copy the descriptor into the message scope before a wait, and use byte integrity only to reject stale/mutated buffers. Registry misses, unknown transforms and generation mismatches retain literal English. Pointer offsets inside object buffers and `releaseobuf` reuse need explicit handling; accepting any pointer within an old buffer is insufficient.

For monsters, observe only the ordinary branch of `do_name.c:x_monnam:827–1031` after native public choices. The `do_it` branch (`876–883`) intentionally returns `it`/`someone`/`something`, including a possible native random choice; never attach true monster identity there. Priest/minion, shopkeeper, hallucination, custom given names and mplayer-rank branches remain fallback until separately specified. Use the original computed `do_mappear`, not `M_AP_TYPE` alone: `SUPPRESS_MAPPEARANCE` changes which native label is intentionally public. Bind the exact returned `pm_name` pointer and the selected appearance species when that branch used it (`907–912`). Preserve final native article, adjective, invisibility and saddle decisions; do not derive them again from true `mdat`. Capitalization/suffix adapters that mutate returned buffers must explicitly rebind their transform or fail closed.

For objects, **name production already changes native knowledge**: `objnam.c:xname` clears certain `known` flags (`625–626`), observes objects (`627–628`), sets cleric `bknown` (`629–630`) and may discover an artifact (`660–661`). Keep those calls exactly once; observers must not replay `xname`/`doname`/`observe_object`. Bind the original branch's selected `actualn`, `dn` or generic class label, not the object's true `otyp`. `OBJ_DESCR` follows the shuffled description index: the nested ID must represent that public appearance label, without exporting an unidentified object's actual type. Knowledge and generic-name guards differ by class (`673–743` and later branches); unsupported class/custom-name/plural/quantity/PREFIX combinations remain English until covered. Any translated adjective, charge, BUC, artifact or corpse information must originate in the exact already-visible native branch.

No additional name lookup, property mutation, sound/handler invocation, locale-dependent native decision or random choice is authorized by this registry design. Native English must continue to be the input to its original consumers. The registry and nested-event formatter need tests for reuse, recursion, aliases, unknown names, hallucination, mimic appearances, unidentified objects and unchanged native RNG/state/input traces before a runtime coverage claim.

The concrete monster generator was subsequently reviewed. Its final ordinary-branch hook uses `do_mappear`, the original chosen `pm_name`, a snapshot of the article before `buf2` concatenation, and the native saddle decision. A discovered empty-adjective edge was corrected by the parent: a non-null `""` adjective still causes the original function to append a space, so the supported guard must be strict `!adjective`; otherwise the descriptor drops visible whitespace. `permonst.pmidx`, `NUM_MGENDERS` and `HIGH_PM = NUMMONS - 1` were verified in the official headers. The current 32-slot registry uses explicit invalidation and byte-integrity rejection; it does not export a generation counter. No runtime or C compilation was performed by this review.

The delegated object implementation is `tools/instrument-semantic-objects.py`, SHA-256 `43838b43394b274beb9231116b439d552e1bd6ad459182d9beadf2ab02a80e4c`, 19,494 bytes at this checkpoint. Its default generates a review patch/audit; optional apply composes exact anchors with an existing working copy and rejects duplicate hooks. Python syntax and in-memory instrumentation of both pristine and current working `objnam.c` passed, with 66 observation hooks and unchanged counts of every original native function call. No patch artifact or working-source apply was executed by this reviewer.

Object hooks capture `oc_name_idx` only in branches selecting `actualn`, `oc_descr_idx` only in branches selecting `dn`, and no index for generic noun branches. The shared registry verifies pointer identity against the selected `obj_descr` field and retains the completed native English string. Original pluralization remains native; Japanese recipe nouns do not receive an English plural suffix. Range invalidation surrounds the original next-buffer selection and original release/decrement. Samurai aliases that no longer match a canonical selected pointer fail closed. Complex names and the entire native game-over-decoration branch conservatively remain fallback. Initial support covers ordinary class/name/appearance recipes; it does not claim `doname` quantity, charges, BUC/properties, corpses, tins or the other exclusions listed in the generator.

The engine's later quest protocol supplies native sequence/index/count/final/capture-complete/window and resolved source identities, with a cumulative conflict-free argument union. The host may replace a paragraph only after all unique accepted rows and the complete final capture have arrived. A further review concern is **per-row public context**: `vpline` can consume an accessibility location on the first row while the final row is plain. Rendering from only the final envelope would lose the first qualifier. Differing/nonempty location context and incompatible attributes/history/urgent semantics require explicit group coverage or an all-original-English fallback. This concern was sent to the browser and engine owners; it is not certified fixed by this document. History-only synopsis remains unbound English in the proposed first implementation.

## Memory evidence and scheduling estimate

`tests/results/browser-resource-final.json` (SHA-256 `170b63587f2ff9405d25305eb4d3af96ad3f6eab90332815b3a91e000cbbafd3`) records one active WASM page, 25,639 ms elapsed and zero owned processes after completion. Before launch it recorded 5,559,521,280 free physical bytes (5.18 GiB) and 7,331,364,864 bytes commit headroom (6.83 GiB). After completion those were 5,604,270,080 and 7,367,012,352 bytes. It explicitly says `peakMemoryMeasured: false`. These are system snapshots, not a browser/process peak measurement.

The reference `build/engine-manifest.json` records 170 C/Lua/ABI inputs, a 12,761,098-byte Rust library and 48.92 seconds for the recorded build. The original object inputs total 6,032,708 bytes. Link flags reserve 64 MiB initial WASM linear memory, with growth enabled; the 4 MiB native stack and 1 MiB Asyncify stack are within that memory, not additional host-process totals. None of the inspected build logs/manifests measures compiler/linker/wasm-opt peak working set or commit. Disk sizes and elapsed time cannot establish RAM requirements.

For parent scheduling only, reserve an **unmeasured conservative 2–4 GiB incremental budget** for one build/link job and keep compiler/linker work separate from browser work. This is a planning estimate, not a measured upper bound or permission to override the memory hold. On the next authorized heavy run, sample the owned process tree and global physical/commit headroom; reduce compiler worker count when headroom is marginal. No compiler, browser, server or memory sampler was started for this audit.
