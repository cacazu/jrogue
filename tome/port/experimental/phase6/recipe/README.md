# Independent phase6 source recipe

This selection stages only into `tome/port/experimental/phase6`. It preserves the existing default 496-file `port/STAGING-MANIFEST.json`, `port/CURRENT-CHECKPOINT.json`, every selected default file and `tome/STATUS.json`. It does not activate a default profile, copy original archives or saves, launch builds/browsers/tests, use Git, or publish a Site.

The parent owns execution. The author has written source and reviewed existing bounded evidence only. `complete` and `full_renderer_ready` remain false. The portable factory and rebased manifests are new source and need their own measured browser run; matching historical artifact hashes does not validate a new route factory.

The bounded selection contains 199 explicit original-workspace files and five recipe files. No recursive source selection occurs. The four changed merged catalog outputs are separately approved selections, not copies of the baseline catalog tree. Copying and hashing use 128 KiB chunks; large catalog JSON is never parsed by the helper. The only files selected beneath Rust `target` trees are the four exact tested release WASM artifacts. Native build folders contribute only their tested JS/WASM pair and link-result JSON. Original upstream ZIP/TEAM/TEAE archives remain read-only dependencies.

## Approval and execution

From the original task workspace, the parent reads and approves `selection.json` and the recipe source, then hashes that exact file. The following are examples for the parent; authoring these instructions has not run either operation:

```powershell
$selectionDigest = (Get-FileHash -LiteralPath .\phase6-staging-work\selection.json -Algorithm SHA256).Hash.ToLowerInvariant()
& 'C:\Users\kit\emsdk\python\3.13.3_64bit\python.exe' .\phase6-staging-work\stage_phase6.py freeze --reviewed-selection-sha256 $selectionDigest
```

`freeze` writes only owned `phase6-staging-work/reviewed-freeze.json`. It rejects any default discrepancy or selected artifact mismatch, validates the actual passed evidence and measured-job endings, reconstructs the exact compatibility response bytes, and produces deterministic rebased manifests plus their hashes. It records current source identities separately from the historical semantic source-freeze identities, including explicit mismatches for edited harness files. It does not stage anything.

After reviewing this concrete freeze and its historical/current identity differences, the parent approves its SHA256 and performs the isolated copy:

```powershell
$approvedDigest = (Get-FileHash -LiteralPath .\phase6-staging-work\reviewed-freeze.json -Algorithm SHA256).Hash.ToLowerInvariant()
& 'C:\Users\kit\emsdk\python\3.13.3_64bit\python.exe' .\phase6-staging-work\stage_phase6.py stage --freeze .\phase6-staging-work\reviewed-freeze.json --approved-freeze-sha256 $approvedDigest
```

`stage` checks the approval hash, all original selection bytes, all generated bytes and the complete default guard before writing, uses exclusive creates into an empty isolated destination, verifies each copied hash, then rechecks the default guard. The final target must remain the literal `experimental/phase6` child of resolved `port`; symlinks and junctions are rejected, with confinement rechecked immediately before the first write. It refuses an occupied experimental destination and performs no delete or overwrite. A failed partial stage requires parent review; it is never automatically removed.

Output is an isolated `PHASE6-MANIFEST.json`, `APPROVED-FREEZE.json`, `STATUS.json`, `recipe/`, explicitly selected `workspace/` source/evidence files, compact `dist/` artifacts and `portable/` adapters/manifests. Status reports historical verification and new portable-runtime verification as distinct facts.

## Portable runtime dependencies

`portable/profile_server.mjs` imports the existing original range server via `../../../kernel/bootstrap/original_range_server.mjs`. That literal path resolves from `port/experimental/phase6/portable` to `port/kernel/bootstrap`. It validates the approved freeze digest, every selected/generated staged byte, all 496 default dependencies and the default checkpoint metadata before constructing any routes. An optional `expectedFreezeSha` argument allows the parent to supply the externally approved hash again. Importing the factory or CLI launches nothing. The guarded `portable/run-local.mjs` imports the heavy factory only when explicitly invoked as the main script, binds exactly `127.0.0.1`, never opens a browser, and closes only its owned HTTP server on SIGINT/SIGTERM.

The four wrapper factories are `portable/physical_server.mjs`, `prepared_server.mjs`, `semantic_server.mjs` and `planar_server.mjs`. They export `createTomeServer` for the existing parent harness. Exact entrypoints and report expressions are recorded in `portable/profile-config.json`. For a parent-owned local run after staging:

```powershell
node .\tome\port\experimental\phase6\portable\run-local.mjs --profile semantic --port 0 --expected-freeze-sha256 <approved-freeze-hash>
```

The CLI prints `TOME_PHASE6_LOCAL_SERVER` with the actual localhost URL/port, explicit profile, entry, report expression and approved freeze SHA. The path shown is relative to the shared repository; use its absolute path when working from task-10. It does not alter the immutable authoring manifest. A later measured proof belongs in a separate `RUNTIME-VALIDATION.json` and experimental status update, without rewriting selected source/proof bytes.

 Original static scripts, compiled artifact responses, historical manifests and historical source-freeze responses retain their bytes. The compatibility script is reconstructed using the two exact original in-memory substitutions, then frozen and compared against its actual served proof hash.

The original range server receives explicit selected native/retained/semantic build roots. Existing default bootstrap static modules, retained browser modules, semantic bridge, catalog base, reviewed format policy and dream extension remain explicit immutable dependencies. Checkpoint routes reference existing `port/kernel/save` files. Reviewed semantic routes override only the explicitly selected four merged outputs and the exact reviewed producer routes. Raw source manifests and source-freeze JSON remain historical identity evidence. A new portable manifest is checked separately; an old source-freeze is never relabeled as current or silently disabled.

Every VFS physical locator is rebased relative to its own `portable/vfs/<profile>.json`. Original virtual paths, directory inputs, source archive identity, mount ordering and AsciiMap/SavefilePipe leaves retain their original metadata. Shared default leaves must be in the preserved 496-file selection; unknown external/workspace roots and symlinks are rejected. Upstream paths resolve to the existing read-only `tome/upstream` tree. No assets are copied, and moving the port without its audited upstream dependencies does not make this a standalone redistributable package.

Compiled distributions are the exact tested artifact bytes. Link commands and seam source names are retained as historical reports. The helper also compares current native seam source hashes with their recorded compile-time SHA256 and records the exact selected/shared source reference. It rejects a native seam discrepancy and rechecks these bindings before writing. Any input lacking a selected/shared portable reference remains an explicit original-workspace rebuild dependency. Unchanged artifact bytes do not establish that a later edited C/Lua/JS harness source was rebuilt or retested. The phase6 source audit and current/historical mismatches remain visible in the manifest.

## Remaining scope

Prepared TMP1 captures original draw geometry/order/transforms/seen state but omits leased texture/program/uniform/FBO and callback continuation needed for complete Rust rendering. Render cache hits must use original continuation, not force map changes or rerun callbacks/RNG. Production turn barriers, named RNG-bank activation, original UI/campaign flows and full text coverage remain incomplete. External Sites are not requested or performed for this local-only milestone. This staging milestone supplies independent, reviewable experiments; it makes no full renderer, whole-game or full translation completion claim.
