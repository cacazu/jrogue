# Fresh original canvas identity and pointer admission

Source-only candidate. No build, tests, browser run, current host edit, or original source change was performed. The exact original/SDK resize contracts and source hashes are in `../RESIZE-CONTRACT-AUDIT.md`.

Pinned SDL hardcodes `#canvas` in its Emscripten backend. The current physical host uses `#original`; the pinned SDK's default selector resolver does not substitute `Module.canvas` for that selector. This can leave a 1280x720 drawing buffer while SDL/original screen/viewport become 800x600. Parent must verify this in the real generated runtime. The clean fix is consistent selector identity before the original creates its SDL window, not a guessed correction to hit coordinates.

Only in a separate fresh variant:

1. Capture the intended canvas object, call `prepareFreshNativeCanvas(canvas, {freshDocument:true})` before constructing the native factory, and pass that same object to the unchanged factory. Update variant-only CSS selectors if they use the old id. Refuse another `#canvas` element or a duplicate lease. Do not rename an initialized canvas.
2. Link the additive `tome_display_contract.c` with the actual physical/checkpoint objects and original include paths. Export `tome_platform_canvas_fresh` and `tome_platform_display_contract`. Required dependencies are original `window`, `screen`, `maincontext`, `screen_zoom`, `current_game`, actual Lua state accessor, and existing physical/checkpoint gates.
3. Immediately before the genuine native initializer, call `lease.beforeNativeInit(actualModule)`. It verifies that the actual SDL/GL globals are still fresh and locks the lease before initialization, even when init later fails. Rollback is allowed only before this point. Do not call another initializer or reset native fields.
4. Keep original init, start, original baseline draw, scheduled event drain, and actual resolution callbacks unchanged. At a completed original root frame, copy the borrowed display-contract string immediately and validate SDL window, original screen surface, original zoom/logical size, actual raw Game w/h, canvas buffer, GL drawing buffer, selector, and root viewport.
5. Insert `admittedPointerPoint` around the existing physical host's unchanged `point()` mapping in the derivative variant. Supply the actual latest physical status. Reject a mismatch/busy checkpoint explicitly; never resize, pump events, alter Game fields, change pointer scale heuristically, or dispatch an extra motion/button event in this gate.

The native getter reads the existing screen pointer rather than calling SDL_GetWindowSurface, and observes raw numeric Game w/h rather than invoking Lua getters or metamethods. It checks the actual GL context's canvas/default framebuffer and current viewport; root-frame sampling matters because original offscreen/FBO passes legitimately use other viewports. Logical sizes reproduce the original C float division before promotion to Lua double, and the JavaScript assertion uses matching Math.fround operations and exact Game equality, without a geometric tolerance. Nonfinite unknown Game fields emit finite zero diagnostics with game_known=false. It does write diagnostic scratch/native stack and restore the Lua stack, so keep it outside the synchronous Rust-only whole-heap purity bracket. It is not a whole-native-memory-pure getter.

Semantic diagnostics are in `en.json` and `ja.json`; the parent must integrate these finite IDs before exposing failures. A pointer event blocked while an original resize/action/save is settling must remain blocked or require an explicit subsequent user event. Do not replay stale coordinates on a hidden timer.

Root acceptance requires original native 800x600 and another actual original resolution, CSS scaling, nontrivial original screen zoom, real original menu hit coordinates, window-resize event ordering, original onResolutionChange, mobile taps, and checkpoint exclusion. Prove exact physical coordinates against the real drawing buffer and original handlers. Do not compare the Game logical width to physical buffer width when zoom differs. Full renderer/mobile/IME support remains separate.
