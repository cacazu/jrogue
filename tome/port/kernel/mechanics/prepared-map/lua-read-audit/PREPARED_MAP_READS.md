# Prepared original map: read-only Lua observations

Static source audit of unchanged ToME/T-Engine 1.7.6. No Lua/game execution, compiler, or browser was used. No existing source or adapter was changed. `E:` denotes `game/engines/te4-1.7.6.teae`; `T:` denotes `game/modules/tome-1.7.6.team`. `source-evidence.json` contains bounded original excerpts with full-member SHA256 hashes.

The original Lua has useful prepared visibility and entity caches, but **does not retain a complete Lua per-cell draw buffer**. Map-object layers selected by original rules are built into a local `mos` table, then transferred to the native C map. Reconstructing sprites or glyphs from gameplay `map.map` would reimplement selection/order and could expose invisible actors or unknown traps. A faithful replay needs the original prepared native objects or the actual ordered native draw commands; Lua raw reads can accompany that capture as metadata.

## Concrete cached fields

All cell arrays below use the original zero-based flattened index `i = x + y * map.w`. Preserve false/nil/numeric values without converting all truthy values to a single boolean. The original arrays have callable metatables; raw table reads avoid invoking them.

| Existing field | Meaning supported by source | Limits for replay |
| --- | --- | --- |
| `map.seens[i]` | Current prepared seen/intensity value, including ordinary vision, ESP, detection and special senses. Set through Map apply functions and Player.playerFOV. | A positive value does not identify *why* a cell is visible, nor independently decide every map object's visibility. |
| `map.infovs[i]` | Ordinary LOS/FOV membership recorded by Map.apply at651, independent of whether the cell is lit. | ESP/detection writes can make a cell seen without this flag. |
| `map.lites[i]` | Stored map lighting flag; propagated into native setLite. | **Not the final dynamic lighting result.** Player/other entity light writes through applyExtraLite into seens without setting lites. |
| `map.remembers[i]` | Prepared remembered-cell flag, mirrored into native setRemember. | Does not imply an actor/trap should be drawn; map-object display_on_remember and known/visibility filtering matter. |
| `map.has_seens[i]` | Historical seen flag updated by regular seen/apply paths. | Not equivalent to current seen; Map.applyESP only writes seens/native seen, without setting has_seens. |
| `map.map[i]` | Gameplay entity associations at terrain1/trap50/actor100/projectile500/object1000/etc. | Not a prepared visible/rendered stack. Unknown/invisible entities remain in gameplay storage. |
| `player.can_see_cache[actor]["nil/nil"]` | Cached default actor visibility decision/chance from original canSee. Result is `{boolean, chance}`. | May be absent/stale/reset; not a complete prepared map-layer ledger. Do not call canSee to fill a missing entry. |
| `player.can_see_cache[actor]["false/0"]` | Separate cache key used by original Map.applyESP's `canSee(a,false,0,true)` call. | Distinct from the default visibility key; fourth argument is not a parameter of original ToME canSee. Do not merge the two entries. |
| `player.fov.actors` / `actors_dist`; `fov_last_x/y/turn/change`, `fov_computed` | Stored ordinary FOV actor geometry/distance and markers from ActorFOV. | Several ESP/sense passes use no_store; these tables are not the complete seen/display list and do not independently solve invisibility. |
| Entity `_mo`, `_last_mo`, `_shader` | Previously generated opaque native map objects/shader. | Incomplete as Lua-layer descriptions: replace_display, add_displays, chained add_mos, extra textures and explicit z have already been assembled natively. |
| `map.effects`, `z_effects[z]`; effect `grids`, `seen_grids`, `seen`, `overlay` | Existing effect state and z membership; seen_grids/seen are prepared by zDisplay's calcEffectVisibility. | No complete emitted shader/particle command list. A direct call to calcEffectVisibility mutates these caches. |
| `map.particles`, `z_particles[z]`, `particles_todel`; particle x/y/radius/zdepth/args/ps | Existing particle emitter membership/configuration and native worker handle. | Worker particle positions/rendering are not a complete Lua draw buffer. Removal callbacks can perform real combat/world mutations. |
| `map.emotes` | Existing emote objects/duration/render resources. | Display advances duration/removes emotes; reading configuration does not reproduce an already emitted frame. |
| `map.w/h`, `mx/my`, `display_x/y`, `viewport`, `tile_w/h`, `zoom`; color_shown/obscure | Cached map dimensions, view geometry and style configured by original setters. | Smooth-scroll/move animation offsets, per-object scaling and hex offsets are applied by native rendering; simple tile rectangles are insufficient for exact frame geometry. Some defaults are class fields, so resolve known plain class tables rather than invoking helpers. |

Initialization/array getter-setter evidence: E:engine/Map.lua210–224 and320–377. Read `rawget(rawget(map,"seens"),i)` only after validating the owning table exists; do the same for the other instance arrays. Copy values into a new adapter-owned packet; retain no mutable game tables in a replay packet. Copy an existing can_see_cache entry by raw identity lookup and preserve missing/false separately. These are suggested read operations, not executed code in this audit.

## Where layers are actually prepared

E:engine/Map.lua469–550 `updateMap(x,y)` creates `local mos={}` at473. The original generic path loads terrain, known traps, objects, visible actors and projectiles into it. Trap inclusion calls original `knownBy(actor_player)` at495; actor inclusion calls original `actor_player:canSee(a)` at512. Generic base z slots are terrain1, trap4, object7 (stack indicator9), actor10, projectile13. A supplied `updateMapDisplay` override fills that same local table at524. The only final per-cell layer persistence in this function is **`self._map:setGrid(x,y,mos)` at542**, to the native map. No Lua field retaining that complete per-cell mos array is assigned here.

Entity preparation is not a simple one-entity/one-layer mapping. E:engine/Entity.lua521–540 substitutes `replace_display`, calls makeMapObject repeatedly for additional displays, honors explicit `dz` instead of default slots, updates `_mo` and `_last_mo`, then defines Lua display callbacks. makeMapObject367–498 creates native objects with already evaluated display_on_seen/remember/unknown, offsets/sizes/scale, textures, animation/tint, chained add_mos, optional function-valued texture definitions and shader objects. Calling getMapObjects/makeMapObject during a snapshot performs preparation and callback/resource creation; existing `_mo` alone cannot enumerate the full assembled stack from Lua.

`Entity.__mo_final_repo` caches standalone entity textures/surfaces by `"w x h"` key (`getEntityFinalSurface/Texture`,636–680). Those are not a viewport draw buffer or a cell visibility/order cache. The getter methods themselves can call getMapObjects and native render-to-texture when absent. Likewise, Tiles.repo/texture_store (E:engine/Tiles.lua57–58) are asset caches, not per-cell emitted geometry.

## The original ASCII path has a different layer contract

ToME selects the genuine ASCII override via T:mod/load.lua34–35. T:mod/class/AsciiMap.lua24–25 modifies the existing engine.Map class; its updateMap29–111 still uses a local mos and filters known traps/visible actors. It writes terrain, trap, object and actor at **slot1** in that order (50/56/63/73), so later eligible entries replace earlier slot contents. Projectile uses slot2 (80), with object stack indicator9 when configured. Native setGrid receives the final local table at102. Therefore a fixed generic terrain/trap/object/actor z scheme would be wrong for original ASCII mode. Capture the actual selected mode's prepared native stack.

T:mod/class/MapEffects.lua modifies effect naming/source behavior, not the default per-cell layer selection. This audit inspected that modifier and the ASCII override because mod/load imports them; it does not assume arbitrary addon updateMapDisplay implementations preserve the defaults.

## Prepared visibility preserves original rules; recomputation is not a query

T:mod/class/Game.lua1825–1827 `updateFOV` calls Player.playerFOV. That function starts by cleaning FOV (T:mod/class/Player.lua555), then prepares wilderness/ESP/detection/omnivision/arcane-eye/marked/preternatural/shadow/minion vision, followed by normal sight and dynamic illumination; normal/light passes are explicitly last (719–739). Blindness still computes actor FOV for NPC targeting (743), and postFOVCombatCheck runs at749. These passes can discover traps/update maps, set actor effects, invoke custom detection callbacks, and change simulation state. They cannot be replaced by a generic LOS query in snapshot code.

Map.apply (E:engine/Map.lua649–658) records infovs then marks a lit cell seen/remembered. applyExtraLite (663–673) requires prior infovs and folds extra light into seens. applyLite (677–685) can mark a cell directly seen. applyESP (690–697) marks actor cells seen after original canSee with default false/chance0. All mutate native/Lua state. The final numeric seens array preserves the assembled result but intentionally does not retain separate ESP/sense/torch provenance masks.

T:mod/class/Actor.lua7491–7507 canSee creates/updates can_see_cache, can execute canSeeNoCache, and updates `_mo:onSeen(res)` for player/default checks. canSeeNoCache evaluates ESP/blindness/concealment/invisibility/stealth and calls `rng.percent` when chance is below100 (7473). resetCanSeeCache replaces its table at7512. Neither canSee nor canSeeNoCache is an acceptable readonly missing-cache fallback. ActorFOV.computeFOV also replaces FOV tables/markers and invokes actor seen_by/updateFOV paths (E:engine/interface/ActorFOV.lua49–129).

## Original display order and capture boundary

Map writes/removals immediately call updateMap (E:engine/Map.lua559–588), preparing native cell objects, but mark `map.changed` and leave visibility refresh for the original preparation/display sequence. `redisplay` (409–417) rebuilds every native grid and restores seen/remember/light; `recreate`/loaded also rebuild native state. They are mutating operations, not snapshot accessors. `map.finished`, changed and clean_fov are lifecycle flags, not a prepared-frame generation identifier.

T:mod/class/Game.lua1856–1857 performs the explicit changed-map FOV pass, then optional display_prepare/background, original native map display, foreground/weather, and FBO/posteffect/target stages (1868–1904). E:engine/Map.lua611 calls native `_map:toScreen`; zDisplay624–628 computes effect visibility, particles and effects during native ordered z callbacks. After native draw returns, Map.display flushes particle removals615, clears changed619 and sets clean_fov620. Earlier callback audit/native source confirms the native second FOV occurs after map-object/z callbacks and before that Lua removal flush; Meteor removal can then change the world after the map draw.

Consequently, **a raw state snapshot taken at the end of a full preparation call need not describe the objects/visibility that were actually emitted earlier in that frame**. Record geometry/draw operations at their original ordered native slots, with the appropriate state metadata for that slot. Do not defer callbacks to frame end or rederive that earlier draw from later gameplay arrays. Repeated Rust replay must consume immutable captured data and invoke none of the original display/FOV/visibility callbacks.

The inspected Lua entry points do not produce a retained list of colored/textured vertices. Game.fbo/fbo2 and Map.fbo/fbo_shader refer to native render resources and postprocessing, not a Lua command packet. Map.display's old comment about returning the same surface does not provide a Lua surface return/buffer in its actual611–620 body. Seen shading itself is native `_map:drawSeensTexture` (T:mod/class/Game.lua1834–1836), and line grids are native calls1883/1902. Weather, targets, tactical frames, particles, emotes, level background/foreground and shaders add output outside the prepared per-cell base objects.

A bounded read-only Lua packet can report already cached arrays, view metadata and lifecycle markers. Full mechanics-faithful pixels/layers require the parent's native command/object capture, including declared coverage limits for dynamic textures, FBOs/shaders/particles/overlays. No complete pure map renderer or runtime visibility/render test is claimed by this audit.
