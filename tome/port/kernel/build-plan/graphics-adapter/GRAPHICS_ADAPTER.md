# Browser graphics adapter for retained original T-Engine

`tome_graphics_adapter.c` and `tome_glu_quadric.c` supply the eleven graphics symbols measured missing by `native-core-work/logs/original-archive-link.txt`. Upstream files are unchanged. These are graphics platform adapters, not gameplay implementations.

Compile the C files as C11 with the existing Emscripten compiler. The earlier readback-only objects were checked with installed Emscripten Clang 6.0.8 using `-O2 -Wall -Wextra -Werror`; the current upload-wrapper revision must be compiled and measured by the parent. Link both alongside the original 23 core objects and fifteen dependency archives, with `-Wl,--wrap=glewInit -Wl,--wrap=glTexImage2D -Wl,--wrap=glTexSubImage2D -sLEGACY_GL_EMULATION=1 -lm` and the parent's existing SDL/image/TTF/audio ports.

The `glewInit` wrapper calls the public original initializer through `__real_glewInit` after installing context hooks. The non-MX source makes `glewContextInit` static, so calling that function from another object is invalid. The public initializer populates real OpenGL function pointers and feature probes first, then its GLX phase reports `GLEW_ERROR_GLX_VERSION_11_ONLY` when SDL has no GLX entrypoints. The browser bootstrap accepts that specific unavailable-platform status while propagating every other initialization failure. The retained GLX procedure lookup delegates to `SDL_GL_GetProcAddress`; GLX version/extension probes truthfully return unavailable. No undefined-symbol suppression or invented GL feature flags are used.

All original `glPushAttrib` uses in `core_lua.c` and `map.c` request `GL_VIEWPORT_BIT`. The adapter keeps a real nested sixteen-entry stack and restores both viewport and depth range. Overflow, underflow, and unsupported attribute groups enter the GL error channel.

Texture dimensions are recorded when the real WebGL context allocates images, including direct SDL/JS allocations. This enables `glGetTexLevelParameteriv` instead of the installed SDK's aborting legacy implementation. `glGetTexImage` uses a temporary framebuffer, returns actual RGBA/RGB/BGRA unsigned-byte texels, and observes pack alignment, row length, and row/pixel skips. Readback restores the old read/draw framebuffer and pixel-store state and keeps texture bindings intact.

The current upload wrappers normalize original C calls before the SDK's pixel-data helper: desktop internal component counts 3/4 become RGB/RGBA; RGB8/RGBA8 use unsized internals on WebGL1 and retain sized internals on WebGL2; BGR/BGRA bytes are copied with their red/blue channels exchanged. RGB-to-RGBA uploads supply opaque alpha, and RGBA-to-RGB uploads discard alpha as the requested storage format requires. Source row alignment and WebGL2 row length/skips are honored, then restored after a tightly packed real-byte upload. Sub-image conversion follows the allocated texture's channel count. Unsupported formats/types/PBO paths report an explicit GL error. SDK functions/procedure tables remain intact because interception uses linker wrappers instead of redefining the SDK's upload imports.

The original allocations include `core_lua.c:297` three/four-channel surface textures, `core_lua.c:1586` RGBA, `core_lua.c:2450,2744` RGBA8 framebuffers, `map.c:553` RGBA8, `map.c:690,2010` BGRA uploads, `noise.c:212,324,367` RGB8, and `wait.c:139` three-channel storage. All three readback calls (`core_lua.c:1386,1574,3281`) use level zero and unsigned bytes. When a source texture cannot attach directly, a real sampler shader renders its level-zero texels into an RGBA texture before readback. This fallback uses an isolated vertex-array object and restores program, VAO, buffer, viewport, color mask, enables, active texture, texture bindings/parameters, and WebGL2 sampler binding.

Coverage is deliberately bounded by these source calls: this adapter does not claim every desktop texture format, arbitrary mip-level conversion, pixel-pack buffers, sRGB raw-byte semantics, or every attribute group. A framebuffer-incompatible upper mip, absent VAO support, unsupported type/format, pixel-pack buffer, shader failure, or framebuffer failure reports an explicit GL error. Original supplied allocations also pass through the SDK's legacy texture-upload emulation; real-browser tests must check those paths.

`test-graphics-logic.mjs` evaluates the exact production EM_JS bodies against a state/pixel recorder. The earlier WebGL1/WebGL2 contract checks passed dimension tracking, RGBA/RGB/BGRA layout, alignment/skips, framebuffer restoration, nested attributes/errors, mip dimensions, RGBA conversion-state restoration, and shader-failure cleanup. New upload-wrapper cases have been prepared but are not run by this source-only review; the parent owns the next measured test. **This is a simulated contract test, not real WebGL execution.** The old `logic-test-report.json` remains historical evidence until regenerated. GLU's independent recorder test validates 8,064 actual sphere triangles and state isolation; see `README.md` and `evidence.json` for the GLU-specific scope. Full browser rendering/gameplay fidelity remains the parent's integration test.
