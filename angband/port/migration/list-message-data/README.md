# Live monster and object list projection

Pinned Angband 4.2.6 source commit `f3082213b73f3e463e3d0d60bff4b00462beae6e`.
This source-connected increment owns 33 English/Japanese semantic templates, all 13 original list append sites (9 visible prose producers and 4 native layout-only producers), and both original monster-sort prompt literals. It has source acceptance only until the parent runs the compiled browser milestone.

The original C terminal, keys, collection, sorting, visibility decisions, counts, glyphs and colors remain intact. The browser receives source-order `row.<integer>.label` events in `monster-list` or `object-list`. Row zero owns the original sort prompt and source-captured action key `120` (`x`); data starts at row one. Viewer exit resets its context. Subwindow content is replaced on the next native update. Japanese semantic rows reflow without inserting Japanese bytes into native fixed buffers. Native row glyph/color metadata is not projected by this increment.

Headers use original monster totals or object **entry** totals as applicable. Omitted counts preserve the original native calculations, including `total - entry_index` for objects. Sleep branches and directional comparisons are selected at the original expressions. Existing absolute values are captured once. Zero remains north/west because the original comparison is `<= 0`.

Each name is an owned naming-v2 snapshot copied immediately after the original name producer. Object names are frozen from the original inner 80-byte buffer before `strtok`; the outer 200-byte list buffer is not a descriptor identity. A pending object-row pointer exists only across that native formatter call and clears before clipping. Every copied row is released after its synchronous event.

Both real and NULL-textblock formatter scopes acquire a nesting-safe generic naming-notice suppression token. Descriptor construction and cache remain intact. NULL measurement emits no UI scopes, notices or list rows and copies no row snapshots. Real formatting emits explicit owned rows without duplicate generic description notices. Both early returns and normal completion release the token; saturation cannot release an outer token. Monster hallucinations retain their original notice; the object special formatter still returns false.

Native interactive formatting passes the entire measured `max_height`, even when the terminal viewport is 24 rows. Parent integration therefore uses finite contextual capacities of 2570 object-list widgets and 1255 monster-list widgets rather than the ordinary 512-widget cap. Naming serialization has a hard 128 KiB cap, 32 parts, six inscription entries, 64 cache entries and a 1 MiB total cache budget. The existing 4096 monster-snapshot macro is not enforced. The semantic event's inclusive 128 KiB cap and bounded cache/model budgets can reject oversized custom combinations explicitly; this increment does not assert that every maximum-size combination fits or silently omit native rows.

`source-baseline/` pins each original list producer before integration. `naming-notice-baseline/` pins the narrow port-helper modification separately. `schema.json` records exact role-local source expressions and named types; original line numbers refer to those immutable baselines. Source reconstruction removes only `AB_LIST_TEXT_BEGIN/END` and `AB_LIST_TEXT_INLINE_BEGIN/END` ranges. The paired inline ranges leave the original native expression between them intact.

Validation: `node --test tests/list-message-source.test.mjs`. Compiler, full renderer capacity fixtures, actual list browser interaction, mobile sorting, and locale/save/RNG acceptance remain parent integration gates. This does not claim complete gameplay text translation or a full Rust gameplay rewrite.
