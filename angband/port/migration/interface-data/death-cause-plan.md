# Persisted semantic death cause

The original save and highscore formats retain a completed English string: `save.c:wr_player()` writes `player->died_from`, `load.c:rd_player()` reads it, and `score.c:build_score()` copies it to the 32-byte `high_score.how`. The additive source implementation now captures the causal branch before that provenance is lost. It retains the original bytes and never reconstructs facts by looking up completed English.

Implemented source deliverables are `../../logic/web-death-cause.[ch]`, `../../rust/src/death_cause.rs`, the fourteen annotated original causal/score/parser sources recorded in `../death-data/source-manifest.json`, and 26 reviewed cause templates plus four composed death/score outputs. Six source checks pass. Eight Rust tests are authored but unexecuted here. Parent registration, the v3 platform extension integration, a fresh WASM build and actual death/score/replay browser flows remain required before runtime coverage can be claimed.

The native causal assignment is in `player-util.c:take_hit()`, immediately before the cheat-death prompt/event. Keep that assignment and all damage, warning, bloodlust, RNG and cheat-death branches unchanged. Capture a pending owned semantic cause at the original caller/descriptor production site, then consume it only in the exact lethal branch that copies `died_from`. A declined cheat-death action must clear/replace the metadata at its original recovery branch. Retirement, victory, live/save/panic and interruption assignments need their own source IDs.

The implemented cause reference owns canonical JSON containing only its reviewed source `id` and exact typed `params`. A monster parameter owns the `MonsterDescription` captured from the original descriptor; native entity pointers never enter persisted metadata. Fixed causes use source IDs. User names remain opaque and separate. Both English and Japanese rendering are validated before a cause can be committed. A failed new capture is distinct from absent legacy provenance and prevents a save snapshot from silently omitting the error.

The original native save payload remains unchanged. The agreed v3 envelope sections are `angband.death_cause` version 1 (16 KiB) and `angband.death_scores` version 1 (512 KiB, at most 100 records), within the platform's 1 MiB aggregate extension cap. Snapshot functions return `Result<Option<Vec<u8>>>`: errors fail the save and preserve the preceding valid save, while absent legacy provenance remains explicit. Highscore metadata is keyed by all 126 original record bytes, encoded as 252 hex characters, without modifying the native record or guessing a cause from English. The size follows the fourteen actual char-array fields in `score.h`; its historical 128-byte prose comment does not match that field sum. C asserts the actual native `sizeof`, and a separate source test checks every original field. Metadata is attached only after native ranking has retained that record. Ephemeral live score predictions occupy a separate slot and are excluded from persisted snapshots. Explicit retention follows the exact native retained rows; the adapter does not rank or evict scores itself.

New-game replay resets metadata before `ab_run` and reconstructs it through the original source hooks. A proved loaded-game bootstrap restores its base metadata before `ab_run`; final target metadata is comparison evidence and is never installed early. Final reconstructed bytes must match the target sections before the presentation becomes visible. The source-address registry is reset around parser/session lifetime only and does not clear restored Rust cause/score state. Its 2,048 copied ID entries bind immutable selected source addresses; parser concatenation revokes an old address before native reallocation, and runtime selection never matches completed English.

For an imported legacy save/score that only has English `died_from/how`, preserve the original bytes and report missing semantic provenance through a reviewed compatibility state. Do not mark it translated, fabricate a monster identity or classify generated English as user-authored text. The compatibility state is an explicit coverage limit until a lossless semantic source exists.
