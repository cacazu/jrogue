# Interface source migration checkpoint

This checkpoint connects source-identified menu, setting, item, shop, target, score and curse facts to reviewed English/Japanese catalogs. It uses Angband 4.2.6, upstream commit `f3082213b73f3e463e3d0d60bff4b00462beae6e`. It is a source migration checkpoint; it does not certify complete translation, compilation, browser execution or a complete Rust gameplay port.

`inventory.json` contains 1,092 original string tokens from the twelve owned core UI compilation units. There are 790 candidates after excluding includes, parser/file identities, spacing, numeric-only formats and export markup. These counts include source tables, composed fragments and conditional branches; they do not count proven runtime coverage. The legacy `enabled_in_port` flag means the compilation unit is selected by the core build. It does not prove that every branch is enabled or that every string reaches the browser.

The frozen interface catalog contains 614 reviewed IDs with matching English/Japanese placeholders. The first phase connects 81 fixed native render/dialog expressions, five static action tables, 45 option enum identities (41 selectable options and four score flags), 46 parameterized projections, 48 bundled monster-category identities, and eleven main knowledge actions. The additive death/direct-item phase supplies 35 further IDs: 26 source cause templates, four composed death/score outputs and five item-switch actions. The generic confirmation phase adds151 reviewed IDs and source-bindings for34 ordinary browser get_check calls plus two shared terrain warnings; the native SDL-only call remains excluded. Curse names/descriptions use the shared domain catalog; the 54 authored Japanese values live in `../domain-text-data/ja-authored-curse-review.json` and are excluded from the interface catalog count.

`web-interface-text.[ch]` is a bounded presentation adapter: 64 registered menus and at most 512 source row identities. It contains no RNG, descriptor generation, spell chance or command execution. Contexts have separate replace/reset lifetimes so shop headings, death summaries, knowledge groups and item lists do not clear one another. Native menu effects remain in C; Rust owns menu selection/navigation policy and scroll/object view clamping through the binary ABI in `web-menu-controller.h`.

The Rust application controller copies policy strings before each next decision, captures the caller's initial outgoing event, and copies each returned effect before any callback can open a nested menu. C runs the requested original validity, tag, direction, action, context, refresh, resize or terminal-width operation once and captures its result. Bounds are 4,096 rows/policy bytes and sixteen suspended controllers. Invalid integration state fails explicitly; it never restarts native policy after executing a callback. Degenerate column mouse division is an explicit error boundary, not a parity claim.

The current test set includes ten interface tests, seven death tests and eleven residual tests. All28 passed together with --test-concurrency=1 in587.46ms after the current independent annotation helpers were present; the residual source-test-results.json records the command and result. Compilation and real-browser acceptance remain separate. They verify byte-for-byte native reconstruction for all twelve owned UI files, causal source statement preservation, catalog/placeholder parity, static producer identity, option identity, direct-item input-wait boundaries, absence of duplicate gameplay queries, C/Rust field order/event bits, the original reverse curse index policy, pointer-registry lifetime and score provenance retention. The parent has passed203 native Rust tests including the corrected126-byte native score identity and opaque parser-token support; newer source changes still require the final WASM/browser gate. These source checks do not replace compilation or actual browser verification.

The first naming/menu/history build succeeded with 729 exact source inputs preserved under `../../tests/first-naming-build-snapshot/`; its fingerprint is `7397f7c9061b4de2e3c5cbada6f7e3b19dd75ba243b7d3ce4ca6a7c6d83d14aa`. Its actual inventory browser assertion exposed the direct item-menu capture gap described above. The additive correction is source-tested and awaits a fresh build and mandatory browser rerun; the earlier build is not evidence that the new phase works at runtime.

The generation order was `build-interface.mjs`, `integrate-interface.mjs`, `integrate-knowledge.mjs`, `integrate-curse.mjs`, then `integrate-menu-controller.mjs`. **Do not rerun that pipeline after another owner patches these C files.** It restores the entry snapshots under `source-baseline/`; a coordinated baseline refresh or an in-place source change is required first. The later `integrate-death-and-direct-items.mjs` uses additive in-place source edits and pinned first-build provenance. The pristine upstream source is retained separately by the parent. `native-parity.mjs` removes the tagged interface/death additions and independent root static/clock veneers when comparing the native baseline.
