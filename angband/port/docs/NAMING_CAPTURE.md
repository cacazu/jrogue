# Source-selected naming captures

This phase adds browser-only projections to Angband 4.2.6, upstream commit f3082213b73f3e463e3d0d60bff4b00462beae6e. The original object_desc, object_kind_name, object_base_name, monster_desc and get_mon_name functions execute exactly once. Tagged AB_NAMING additions copy the choices made at their existing source branches. Removing those additions reconstructs the pinned original naming source bytes, including CRLF. The authorized chest_trap_name and steal_monster_item treasure-literal additions satisfy the same function-level parity rule.

The owning KnownObjectDescription and MonsterDescription values use schema_version 2. Each contains mode, native_max_bytes and ordered selected parts, plus monster capitalization. Nothing/unknown/money returns, quantity/articles, ordinary/flavored/book bases, known artifact/ego/aware-kind suffixes, chest winning labels, fuel, known combat bonuses, modifier order, charges, charging, store annotations and player inscriptions are captured at their native selection points. The original predicates, curse aggregates, number_charging, quark lookup, everseen writes, rules and RNG retain their original evaluation order and count. Object CAPITAL remains the original no-op. Monster descriptions cover hidden/visible and forced visibility, all pronouns, reflexives, appositive/possessive/offscreen markers, capitalization and list plurals.

Canonical indices stay in the private source-bindings table. Wire values expose the selected public lexical IDs only. Repeated source lexemes coalesce; unused modifiers are absent. A stripped NAME_COMMA branch exposes only its selected possessive stem ID. Identical someone/someone's choices coalesce female/male indefinite codes, so a suppressed sex is not exported. Fixed artifact/kind/flavor/ego identities require exact pinned source-lexeme verification. This is source identity verification, never matching completed descriptions. Generated scroll titles, generated randart proper names and user inscriptions are copied opaque inputs with explicit origins. Native randart of/quoted attachment is captured from artifact_gen_name's actual lexical contract.

The C helper constructs owned, validated UTF-8 JSON through web-semantic. Each capture is at most 128 KiB; the cache holds at most 64 entries and 1 MiB of JSON. It replaces an entry on every descriptor write to the same native output-buffer address and evicts oldest entries within those limits. Generic naming events use the reviewed naming.object.description/object and naming.monster.description/monster envelopes, channel ui, context descriptions, and the shared synchronous Rust/host ABI. Native output and native gameplay feedback remain intact on a capture failure. Missing, oversized or unmapped captures report complete:false with an explicit reason; they never search English text or resolve deleted objects.

Buffer consumers must copy immediately after the original descriptor call on their actual current branch, before that buffer is overwritten. ab_naming_copy_json_for_buffer writes an owned value into an open semantic parameter; snapshot copy/release APIs support UI rows. A buffer address alone cannot detect an unrelated literal write or reused stack frame. Such producers must invalidate or register a source-selected capture, as the approved treasure branch now does. The cache can evict old facts; a missing entry is explicit. It is not an unbounded ownership guarantee across arbitrary nested workflows.

Subject-address APIs exist solely for the four command handoffs. Feared attack copies immediately after MDESC_DEFAULT; the controlled actor copies immediately after CAPITAL|IND_HID|COMMA and freezes JSON before any actions/deletion; a controlled drop copies immediately after its one live PREFIX|FULL descriptor. They never dereference the subject during cache lookup or act as cross-command entity resolution. General messages and UI rows use output-buffer identity instead. The prior browser drop guard still freezes uintptr_t before drop_near and skips the unsafe native post-drop description only if the original object was consumed; ordinary live-drop rules and energy remain unchanged.

The independent naming catalogs supply authored Japanese composition, counters and lexical names. English uses the original native byte limit; Japanese reflows under the formatter's safe bound. Undefined native cases, including descriptor buffer overflows in raw name-format writes or the former freed-object drop followup, are not claimed to have defined output fidelity.

Source-only validation is in tests/naming-capture-source.test.mjs and tests/command-semantic-integration.test.mjs. These check byte reconstruction, exact original predicate counts, source identities and bilingual endpoints, selected private facts, native no-op behavior, cache ownership and the source-selected treasure path. They do not compile C or run the engine. Root must add logic/web-naming.c to the adapter build, connect the two generic schemas and naming catalogs, and perform the coordinated C/WASM build and real-browser acceptance. The previous accepted binary/publication does not include this new phase until that succeeds.
