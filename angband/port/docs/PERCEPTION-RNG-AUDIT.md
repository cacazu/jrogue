# Native perception and RNG boundary

Angband 4.2.6, upstream commit `f3082213b73f3e463e3d0d60bff4b00462beae6e`, uses its gameplay RNG during some original perception work. A cached browser repaint is pure; an original native map redraw while hallucinating is not. Both behaviors must remain distinguishable to preserve the original game.

This audit changes no original C game processing. `ui-map.c`, `cave-map.c`, and `z-rand.h` are byte-identical to pristine upstream. The WELL generator, `Rand_state_init()` and `Rand_div()` bodies in `z-rand.c` match pristine upstream. That file already contains the separately reviewed replay wrappers for clock/PID observations in `Rand_init()` and `Rand_simple()`; it is not described as an unchanged whole file. Source hashes and exact assertions are in [perception-rng-boundary.json](../migration/perception-rng-boundary.json) and [perception-rng.test.mjs](../tests/perception-rng.test.mjs).

| Original source path | Entropy and mutation |
| --- | --- |
| `cave-map.c map_info()` | When `TMD_IMAGE` is active and the selected grid has neither monster nor first object, `one_in_(128)` may introduce an apparent monster; an `else if` may introduce an apparent object. The random check runs before `FEAT_PERM` in each conjunction. A permanent wall still consumes those checks. Moving the wall guard ahead of them changes the subsequent stream. |
| `ui-map.c hallucinatory_monster()` | `randint0(r_max)` repeats until a named race is selected. It returns the selected race's current attr/char. There is no fixed one-draw guarantee. |
| `ui-map.c hallucinatory_object()` | `randint0(k_max - 1) + 1` repeats until a kind has a name and nonzero attr/char. Its original rejection order matters. |
| `ui-map.c grid_data_as_text()` | Objects are handled before monsters. Either hallucination helper can run; ordinary visible monster handling can also write `mon->attr`. This is not an immutable query over the native cave. |
| `ui-display.c do_animation()` | Each visible `RF_ATTR_MULTI` monster draws `randint1(BASIC_COLORS - 1)`, writes `mon->attr`, sets `PR_MAP | PR_MONLIST`, and advances the flicker counter. `RF_ATTR_FLICKER` follows the existing cycler/fallback path. |

`randint0()`, `randint1()` and `one_in_()` all reach `Rand_div()`. That function chooses the quick generator or WELL according to `Rand_quick` and rejects values outside its partitions. A helper call can therefore consume more than one generator sample even before its own skip loop. No audited perception function swaps to a separate UI generator or restores the gameplay RNG afterward.

`square_light_spot()` emits `EVENT_MAP`. The main terminal's registered `update_maps()` handler calls `map_info()`, then `grid_data_as_text()`, then `Term_queue_char()` and `Term_fresh()`. A whole-map `EVENT_MAP(-1, -1)` calls `prt_map()`, whose row/column traversal follows the same perception calls. `display_map()` for the original small-scale-map command may call `grid_data_as_text()` a second time for a grid which wins its minimap priority comparison. A browser implementation must not add any of these calls to obtain semantic descriptions or to refresh CSS pixels.

`game-world.c` sets `PR_MAP` during constant hallucination after a player action. Its `run_game_loop()` emits `EVENT_ANIMATE` before `process_monsters(player->energy + 1)` in both player-energy loops. The registered `animate()` handler invokes `do_animation()` at those original positions. Changing their ordering or stream affects later monster/world outcomes even if the hallucinated glyph distribution looks similar. `monster_desc()` itself describes the actual visible/pronoun-selected race and does not independently select a random hallucination name; the map and look/target perception paths must be audited separately.

The desktop adapters may call `idle_update()` while waiting. The browser adapter's `TERM_XTRA_EVENT` wait does not call it: it observes the state, synchronizes saves/events, and sleeps for 16 milliseconds until an event is available. `browser_term.never_bored = true` also avoids adding native boredom callbacks. Consequently, browser elapsed idle time and animation frames do not introduce desktop idle-animation draws. This is an explicit platform boundary, not a claim that every desktop terminal has the same idle schedule.

The preserved browser boundary is already suitable for source-faithful isolation:

- Native original command, perception, and animation work runs at its existing location and order. Selected facts and completed terminal cells are copied once into owned Rust/browser models.
- `web/app.js redraw()` calls `drawFrame()` with the cached immutable frame. It has no worker message or C query. The font and browser window-resize handlers call this function only.
- Locale changes call the Rust locale/presentation functions over cached semantic facts. They do not ask native map code to select a different apparent monster or object.
- An explicit terminal-size change is a distinct normalized replay event. It reaches `Term_resize()` and belongs to the original terminal-event continuation. CSS font size and browser viewport repaint are not that event.
- `main-web.c snapshot_rng()` records all 38 words: `Rand_quick`, `Rand_value`, `state_i`, `z0`, `z1`, `z2`, and all 32 `STATE` entries. `emit_state()` and `observe_wait()` observe them before the native terminal outcome. Version 3 saves the owned continuation at the exact pending wait without a native redraw or native save writer. The replay environment separately records clock/PID facts; the snapshot is not a claim to include `Rand_simple()`'s private static seed.

Replacing these native draws with an independent UI RNG, saving/restoring the stream around them, suppressing them, or rescheduling them would alter original processing. No such patch is proposed. New semantic consumers must copy the already-selected source facts rather than re-running `map_info()`, `grid_data_as_text()`, animation, or other native perception logic.

[browser-normal-play.mjs](../tests/browser-normal-play.mjs) is a separate bounded acceptance harness. It starts through normal Human Warrior birth with default options, consumes an original ration, enters the original staircase, explores only the visible/remembered native terminal map, requires a successful source-bound melee capture, saves/resumes that actual combat continuation, compares four further original turns including every RNG word/frame/semantic fact, then seeks natural damage/death through ordinary movement/hold/deeper stairs. It never sends a control chord, wizard command, generated save, or native memory write. Failure to reach a scenario is a failed test with the exact input trace and native state, not accepted wizard evidence. It records maximum depth and explicitly does not claim a normal 100-level campaign.

The source audit and cached-repaint assertions do not prove runtime hallucination acceptance. A separate, clearly labelled original-command hallucination fixture can establish that boundary: reach actual `TMD_IMAGE` through the original effect mechanism; capture all 38 RNG words and owned cells/facts; verify cached repaint/locale roundtrip is identical; invoke the original native redraw command and record its native stream change; then prove the same continuation reproduces that result exactly. Native redraw must not be required to be RNG-pure. Root owns measured browser/build execution after the final engine is frozen.
