# Browser save and deterministic replay

Current browser saves use Rust envelope schema3. Original Angband rules remain authoritative; a complete bootstrap and owned platform/input journal reconstruct the original process to a supported pending request. Identity includes exact engine/data hashes and input/presentation source identities. A mismatching engine is rejected explicitly.

The record retains validated environment files, returned native/platform events, normalized keyboard/text/pointer input, pending packets, text-group/selection/composition/focus metadata and an unsent opaque draft. Replay verifies native state, all 38 WELL RNG words, native wait, cached frame and canonical semantic source evidence. Rendered English/Japanese strings do not enter the evidence digest. Browser repaint, font/viewport and locale changes use copied facts without entering native simulation.

V3 saving at the pending request serializes owned replay state. It does not invoke `savefile_save`, redraw, re-query descriptors or advance RNG, and it does not embed a suspended C stack. Resume validates the bootstrap and environment before mutation, rebuilds the original process while live input/save and outward presentation are suppressed, then restores the copied queue and draft at the verified target. See [REPLAY_V3_SOURCE_INTEGRATION.md](REPLAY_V3_SOURCE_INTEGRATION.md) for source contracts; that document also retains its historical implementation-phase status.

The fixed source baselines read by tests and packaging remain, including `tests/first-naming-build-snapshot/source/`; the current executable is in `build/` and the served package is in `dist/`. The current additional source connections include message recall/search, second-sheet matrices, native menus, look prose, chronological history, knowledge metadata, character exports and chest messages. Matching final-engine browser paths verify recall/search, second-sheet pending restore, native keyboard/mouse menus, selected look/history/knowledge rows and complete Japanese character download with opaque full name/note and consume-once behavior. These representative paths do not execute every listed branch. [verification.json](../verification.json) is the authority for the last accepted engine; source-phase manifests and older snapshots do not validate a changed binary. Each browser evidence directory retains its `results.json` and the run selected by `outputDirectory`; superseded runs and partial downloads are removed.
