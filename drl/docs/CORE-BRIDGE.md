## Input delivery

Original modal waits can drain a down/up event batch before updating the active controller. Browser synthetic/touch key presses therefore send key-down, wait for its real native frame receipt, then send key-up and wait for that frame. Peeking or replay drawing cannot acknowledge delivery. Touch hold/release/cancel preserves native key lifecycle; different keys may coexist while repeated presses of one key stay serialized.

`VEVENT_TEXT` packets are split into chunks of at most 15 UTF16 units, without splitting a code point, because the original input frame's bounded text buffer is narrower than the wire's UTF8 payload. The entire batch is validated before enqueueing. After each text chunk is consumed, later FIFO delivery waits for its real native presentation receipt; the final consumed chunk also remains pending until presentation. The shell/key/text Node tests passed **22 checks**, and the actual browser accepted the exact 18-character name `BrowserMarine_5489`. UTF8 transport does not change the original editor's accepted character policy: native name entry still accepts its original ASCII letters, digits, spaces, apostrophe and underscore.

## Wire version 1

All words are explicitly little endian. Pascal and Rust share neither record layouts nor pointers; the host synchronously copies borrowed Pascal buffers. Both ends validate bounds.

- Input is 128 bytes: 16 words followed by 64 UTF8 bytes. Words encode version, original event ordinal, key/device code, ASCII scalar, modifiers, pressed/repeated bits, x/y, relative x/y, button/state, axis value, device ID, system code and text byte count. Text is at most 63 bytes plus NUL. Original modifier masks remain 256/512/1024 for shift/alt/control. Pointer coordinates begin at 1; map tile `(1,1)` is console `(2,3)`. Frame/draw coordinates begin at 0. Typed input uses `VEVENT_TEXT`; browser suppression of `KEYDOWN.ASCII` text append prevents duplicate insertion while key codes retain command behavior.
- `DRLF` is a 32-byte header plus 2,000 12-byte cells. The header contains magic `0x464c5244`, version, 80 columns, 25 rows, cursor x/y/visibility and glyph encoding. Each cell stores glyph, foreground and background. Encoding 1 is original CP437, encoding 0 a Unicode scalar.
- Draw commands have a 64-byte header and separately borrowed text bytes. Sixteen words encode version, original ordinal, area and clip rectangles, foreground/background/extra color, text encoding and two reserved zeros. Encoding 0 is UTF8; encoding 1 identifies original byte glyphs. Rust applies commands in order. `ColorNone=0xEFFFFFFF` retains transparency.
- Semantic `resolve_text(request,bytes,output,capacity)` uses a two-pass 32 KiB bound. Requests contain `{kind:"native_text",id,english:false,parameters:{name:{kind:"string"|"integer",value:string}}}`. Strings stay verbatim and integers use canonical decimal strings. The connected resolver selects EN/JA UTF8 before width measurement without English fallback.

Other imports are `poll_event`, `event_pending`, `now_ms`, `drl_sleep`, `frame`, `draw_command`, `text_input`, `title`, `rumble`, `text_columns` and `text_fit`. JavaScript marshals memory and delegates services to Rust.
