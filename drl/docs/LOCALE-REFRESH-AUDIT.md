# DRL locale refresh audit

Historical read-only source audit, 2026-10-02, against core `e13315d480a34b6903e12f686a809b43ca2e55c6508464dd05c4263defd3fd98` and Rust `c6715af823749d5365547d52a202f51903561966affc73284f8860e89505ac27`. The audit itself did not implement or execute changes. Original upstream commit remains `a6f965072b3a25b768c91dbced00367f1b57d865`.

Current disposition: core `20e21dafe03105aaae03e821d94392f60ba655b8e9212a126554499213054d60` and Rust `54931a8c74f5dbeb304f2da397d90e9463d8033586cd49f766d0335d20bdfd5e` pass the 22:35–22:36 UTC **15-check primary browser receipt**, including same-open official Help body/title/fixed-key Japanese → English → Japanese on later native frames and the scrolled page, with unchanged bounded DRLP/MT bytes. A separate six-check combat/autorun receipt exists on the same pair. The eight-help-document/23-fixed-assignment slice is source-integrated and compiled; actual refresh proof is limited to the traversed Help path. Inventory/traits/character/detail/hints/messages/plots/confirmations/choices/reports remain open. See [the bounded protocol](../localization/LOCALE-REFRESH-PROTOCOL.md) and [current runtime evidence](ORIGINAL-GAME-RUNTIME-EVIDENCE.json).

The switch immediately translates browser controls and selects the language for future native resolver calls. Current draw-time Help accessors and fixed-input dispatch bypass their former caches; other native text caches are not globally invalidated. Complete current-locale presentation is still unestablished.

## Actual switch and redraw path

1. [`game.mjs`](../port/web/game.mjs), lines 571 and 374–379: the language selector changes the browser `language`, runs `uiLocale()`, and calls `host.setLanguage(language)`. `uiLocale()` updates the document language/title and elements bearing `data-text` or `data-aria`. A running game gets the existing `game.locale_pending` status.
2. [`core-host.mjs`](../port/web/core-host.mjs), lines 124 and 145–146: `setLanguage()` validates and replaces a JavaScript variable. Future `resolve_text` requests override the request's `english` flag from this variable. There is no call to a Pascal locale setter, cache generation update, layer refresh, or queue operation.
3. [`drlbrowsersemantic.pas`](../core-overlay/drl/src/drlbrowsersemantic.pas), lines 26–46, and [`drlsemantictext.pas`](../localization/drlsemantictext.pas), lines 114–129: `DRLText` calls the installed host resolver for each invocation. This boundary does not cache resolved strings. `DRLEnglishText` remains an English-only guard formatter.
4. [`game.mjs`](../port/web/game.mjs), lines 236–255: drawing transport retains an already resolved Rust presentation. `replay()` presents that same value; it cannot reconstruct semantic IDs or translate existing command bytes. Changing the font or viewport can replay existing pixels/text without requesting any native text.
5. [`viorl.pas`](../core-adapted/fpcvalkyrie/src/viorl.pas), lines 213–227: the normal original idle input loop performs `FullUpdate`, sleeps, and checks input. New native draws can therefore resolve *draw-time* IDs without gameplay input. This does not repair values rendered earlier and stored in a field or array.

The browser UI catalogs are projected for both languages at launch in `game.mjs:257–267`, so switching the browser controls does not require a simulation command. The native canvas is different: its current frame and many native fields contain final strings.

## Replayable ledgers already present

These stores retain original identities/guards and semantic input rather than a single permanently translated result:

- [`drlsemanticitemnames.pas`](../localization/overlay/src/drlsemanticitemnames.pas), lines 121–137: `DRLItemNamePresentation` replays the retained item name transition chain through registry/aspect projectors on each call. Matching UID, prototype ID and English name guard are required. It does not need to clear or rewrite the ledger when the language changes. `TItem.PresentationDescription` calls it at the presentation boundary (`dfitem:403–409`), but an already cached view entry still needs reprojection.
- [`drlsemanticfeelings.pas`](../localization/overlay/src/drlsemanticfeelings.pas), lines 247–267: `DRLRepeatSemanticFeeling` validates the original guard and resolves each retained semantic record using the current host language. An old `FCharacter[1]` line containing its previous output remains stale until safely reprojected. Do not clear/recollect the feeling records or rerun level-generation hooks.
- [`drlsemantichistory.pas`](../localization/overlay/src/drlsemantichistory.pas), lines 187–216: `DRLPresentationHistory` checks the original dense-history index and guard, projects retained original parameters, then calls `DRLText`. The ledger itself does not require locale invalidation. Generated mortem/report output that copied its result may still be frozen.

The historical audit identified `History.GetValue([DWord(aIndex)])` selecting a numeric-path overload that read callback parameters instead of the original history table. The scalar `History.GetValue(Variant(aIndex))` fix is now compiled. The historical 13-check milestone and current 15-check receipt capture a nonempty original intro ledger with its unchanged English guard, retained through native Exit/fresh Continue. Wider history presentation remains open; locale switching must not rerun gameplay history hooks to backfill old empty sidecars.

## Operations that must not be reused as invalidation

The following routines include more than presentation work:

- `TPlayerView.ReadCharacter` calls `Player.Statistics.Update()` (`drlplayerview:974`). Original [`drlstatistics.pas`](../native/drl/src/drlstatistics.pas), lines 74–86, writes `real_time`, `real_time_ms`, `game_time`, kill totals and `kills_non_damage` into the domain map. Calling this method because the language changed is not a pure presentation refresh. Replacing this call with a locale-triggered call also would not be made safe by unchanged MT bytes.
- `TDRLIO.Reconfigure` reconfigures audio, resets command bindings, reapplies controller bindings, and rebuilds substitution maps (`drlio:655–724`). Extract the map-only text work; do not use this routine for locale invalidation.
- `TMainMenuView.ReloadArrays` writes `ChallengeType[1..3].Allow` (`drlmainmenuview:1012–1014`). `ReloadChallenge` clears events, resets selection, and may set `FResult.ArchAngel := True` (`1074–1075`, `1103–1104`). A refresh must preserve these choices and flags.
- View constructors/`Initialize` routines commonly clear VTIG events and reset selection or scroll. For example, `TPlayerView.Initialize` also resets class-wide `FTraitPick` (`186–204`). Replacing an open layer is not equivalent to reprojecting its text.
- `GetQuitMessage` selects a quip with `core.visual_random` (`core-adapted/drl/bin/data/drl/main.lua:765–780`). It must not be called again solely for a language switch. This also demonstrates why the gameplay MT witness alone does not cover all relevant random/state changes.
- `TItem.PresentationExtName` can invoke `Hook_OnDescribe` (`dfitem:454–460`). Calling description producers again to rebuild a look hint needs an owner-by-owner read-only proof. Retain the captured hook result instead.
- Refeeding old messages through `TMessages.Add` can alter repeat/group state and invoke the more callback (`vmessages:91–123`). Reflow/project the retained records directly rather than re-emitting historical events.

## Minimal implementation sequence

1. Add a presentation-only locale generation at the host boundary, changed only when the actual language changes. Let the running native continuation read the generation through a synchronous host import at its normal update boundary. Do not call an arbitrary Pascal refresh export reentrantly from the DOM language event while `_start` is suspended. No synthetic keyboard event, simulation command, or RNG call is needed.
2. Reproject stateless draw-time fields and fixed key substitutions first. Resolve help from its validated topic index at draw time so the same open help page, including its body, changes language without reopening or reloading assets. Keep original external/user strings, version numbers, custom text and English guards verbatim.
3. Give each cached view a presentation-only refresh method/generation check, or move its fixed IDs to draw-time projection. Keep view mode, selection, scroll, filters, enabled flags, captured numerical values, and original object identity stable. Split character statistics capture from its text formatting before enabling character refresh.
4. Preserve explicit semantic provenance for messages, hints, plots, choices, confirmations, awards and reports at their producers. A record should retain ID, English guard and typed inputs. Nested item/being/rank names need retained semantic registry/name descriptors or original snapshots, not already translated strings passed as parameters. A generic reverse lookup or replacement of displayed strings cannot recover this safely and is outside the approved semantic-ID approach.
5. Mark the locale applied only after an actual native frame from the refreshed generation is successfully presented. Browser control text may change immediately; the existing pending status should remain until the native frame has applied it. Replay/font renders must not acknowledge a native locale generation or input receipt.

For old literal buffers without semantic provenance, preserve the original literal/fallback and report incomplete coverage. Do not guess an ID from the rendered text or mutate domain names/history to make the display appear translated.

## Required verification and current evidence limits

The historical language test checked host language and bounded DRLP/RNG only. The current primary receipt adds two actual native Help checks: the same open topic changes known body/title/fixed footer in both directions on later native frames, then the scrolled page returns to the same Japanese projection without reopening/resetting. All DRLP/MT bytes remain unchanged. It still does not capture the complete statistics/visual-RNG/world/queue/modal state or prove other cached views refresh.

A meaningful refresh gate should use a fresh original runtime and verify the same open inventory/equipment/traits/character/help/settings/detail/target/message/plot/confirmation/report screens in JA → EN → JA. It should assert known semantic labels and bodies for the applied generation, absence of previous-language labels where the semantic producer is covered, exact external character name, and unchanged selection, scroll, inventory filter, target, held input, original numerical inputs and all relevant RNG streams. Include the help body after closing/reopening, because that catches the asset-lifetime cache. Capture a real historical message and a feeling/history record so the test cannot pass with empty buffers.

Use a complete read-only world/statistics/command/queue witness before claiming full purity. The current DRLP probe is partial. Do not substitute native save serialization: it has gameplay/lifecycle effects and does not establish presentation purity. A targeted statistics witness should specifically demonstrate that repeated locale changes while the character view is open do not rewrite any statistics key.

The original audit recommendations remain historical. The Help/fixed-input slice is now compiled and bounded browser refresh passes; other cache repairs and full text coverage remain independently incomplete.
