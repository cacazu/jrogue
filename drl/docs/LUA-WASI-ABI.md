# Original Lua 5.1.5 WASI and Pascal ABI evidence

The original Lua C interpreter compiles and executes in Node WASI and real Chrome. The mixed Pascal/Lua probe also passes in Node WASI: corrected debug/buffer records, fixed and packed formatters, Japanese semantic callbacks, shared allocation and libc file IO, OOM recovery, 5,000 GC iterations and 2,001 protected Pascal callback errors. The two sampled heaps after repeated errors are both 42,512 bytes. These are interpreter/ABI milestones; original DRL campaign execution remains a separate integration gate.

The mixed probe exposed two concrete problems with bounded, now-tested adapters: the pinned FPC wasm32 compiler fails on original C-varargs calls, and its startup uses a heap position incompatible with the measured external LLD layout. Fixed signatures and protected formatter cleanup address the first; a linker wrapper and one shared Pascal allocator address the second. No pristine source or shared toolchain source was changed. Nested Lua to Pascal browser suspension is the next ABI gate.

## Exact C build

[build.ps1](../experiments/lua-wasi/build.ps1) compiles serially, excluding standalone `lua.c`, `luac.c`, `print.c`, and archives the library. It uses `--target=wasm32-wasip1`, the task-local SDK sysroot, `-O1 -g`, `-mllvm -wasm-enable-sjlj`, `-mllvm -wasm-use-legacy-eh=false`, and explicit official `libclang_rt.builtins.a`. The command probe links `crt1-command.o`, `libc.a`, `libsetjmp.a` and `libwasi-emulated-process-clocks.a`, a 1 MiB stack and 64 MiB maximum memory. The build has no dynamic loading, POSIX subprocess support or filesystem preopens.

The acquired [official WASI setjmp header](https://github.com/WebAssembly/wasi-libc/blob/main/libc-top-half/musl/include/setjmp.h) requires exception-handling support for setjmp/longjmp. Lua uses those for protected evaluation and error recovery. The tested C flags select current exception instructions, matching FPC `-CTwasmexceptions` and the separately built `toolchain/rtl-exnref`. Branchful or legacy RTL must not be silently substituted.

The C-only archive SHA-256 is `7767649b444b2f0ada9f6f3388cf9fcaefbf1597917713897e5e75abd1b8451e`. The C-only authored smoke WASM is `97a5687842af3dbe7f8072d6233c214e3010aeb76b3567e45cba27b0304bfe55`. The additional authored C wrapper archive is separate and changes as the bridge is completed.

## Required ABI corrections

[prepare.mjs](../experiments/lua-wasi/prepare.mjs) copies official sources to the experiment and records every changed file hash in [patch-manifest.json](../experiments/lua-wasi/patch-manifest.json). It does not patch pristine source.

| ABI property | Original mismatch | Probe configuration / measured value |
| --- | --- | --- |
| lua_Integer | Pascal Int64, default C ptrdiff_t becomes i32 on wasm32 | C `LUA_INTEGER=long long`, both 8 bytes; signed ±6,000,000,000 tested |
| lua_Number | Pascal Double | C/Pascal 8-byte f64 |
| pointer / size_t | Pascal pointer/LongWord | wasm32 4 bytes |
| lua_Debug | Pascal omits C lastlinedefined | corrected record 100 bytes; lastlinedefined offset32, short_src36, i_ci96 |
| luaL_Buffer | Pascal hard-codes1024, C uses platform BUFSIZ | force C LUAL_BUFFERSIZE1024; record1036 bytes; 3,000-character use tested |
| C varargs | Original Pascal external `varargs` calls | fixed-signature ABI adapters below; original call shapes cannot compile with current pin |

`lua_Reader`, `lua_Writer`, `lua_Alloc` lengths use 32-bit `size_t`, matching preserved LongWord on this target. C callback result/int/LongBool storage uses i32; callbacks must use cdecl procedure variables. A corrected [vluatypes.inc](../experiments/lua-wasi/pascal-overlay/vluatypes.inc) is provided separately. Full original-binding compilation/runtime validation remains required.

Official Lua `lundump.c:214` includes sizeof(size_t) in compiled-chunk headers and rejects mismatching headers. Native 64-bit bytecode must therefore not be reused as wasm32 source assets. The actual original-core asset packager, `tools/package-core-assets.mjs`, uses the original ForceRaw module loader and `.lua` source files, avoiding that cross-target bytecode assumption. Its real game loading remains part of the parent integration gate.

Official WASI libc lacks `tmpnam`/`L_tmpnam` and `tmpfile`, causing actual compile/link failures. Experiment patches make `os.tmpname`, `io.tmpfile`, `os.execute` raise explicit unavailable-platform errors. `os.clock` uses declared WASI wall-clock process-clock emulation, whose suspension semantics differ from native process CPU time. DRL runtime data uses the original Pascal `core:`/`drl:` module loader; the data-source scan found no active subprocess/temporary-file dependency. Build/helper scripts are separate. These APIs must be audited again if user-created modules are later enabled; the shim must not pretend to provide them.

The platform-error patches pass semantic IDs `error.lua.platform.external-process`, `error.lua.platform.temporary-name` and `error.lua.platform.temporary-file` into the authored C seam `drl_lua_platform_error`. With the original UI API registered, it calls `ui.semantic_text(id, english, {})`, verifies function/string types, retains the original caller's luaL_where prefix and raises the translated Lua-owned result. The original TDRLLua registers UI before loading game scripts; separate early TLuaConfig states and the standalone C interpreter have no UI table and use the explicit English fallback. The original bundled config/metadata does not invoke these unavailable APIs. Canonical EN/JA entries and empty parameter contracts are owned by the text-semantics task. The mixed probe executes all three paths through an actual authored Pascal semantic callback and verifies Japanese bytes. `fpwidestring` and `SetMultiByteConversionCodePage(CP_UTF8)` are required for the tested Pascal string conversions; without them this probe produced `???` despite successful callback dispatch. This callback proof does not certify the complete original-game text catalog.

## Executed interpreter checks and browser imports

[probe.c](../experiments/lua-wasi/probe.c), [node-evidence.json](../experiments/lua-wasi/node-evidence.json), [browser-evidence.json](../experiments/lua-wasi/browser-evidence.json) record actual execution, exit0, Node24.19.0 and real installed Chrome. Both check interpreter identity, loops/tables, UTF-8 byte-string operations, two C callbacks, Int64 API round-trips, nested pcall errors including a C callback's luaL_error, malformed-source recovery, coroutine yield/resume, GC and buffer growth. Pascal callbacks and DRL gameplay are explicitly excluded from that evidence.

The browser WASI host is explicit and local: [browser-host.mjs](../experiments/lua-wasi/browser-host.mjs). The evidence verifies no unsupported call was used. This limited host must be extended with a real virtual filesystem for the original game assets/saves rather than treating smoke coverage as full support.

## Measured compiler and allocator integration problems

The 12-line [probe-varargs.pas](../experiments/lua-wasi/probe-varargs.pas) calls Lua's original `lua_pushfstring` declaration with `%d %s`. Compilation fails with FPC internal error `2021091801` at program end, even without exception/finally code. The [failure log](../experiments/lua-wasi/mixed-build/probe-varargs.pas.log) and [exact command](../experiments/lua-wasi/probe-varargs.pas-commands.json) are retained. Pinned `compiler/wasm32/hlcgcpu.pas:2473` detects an unfinished evaluation stack; original `vluasystem.pas` exhibits the same failure. Removing original gameplay exception ordering is not a valid remedy.

The narrow remedy is [bridge.c](../experiments/lua-wasi/bridge.c), whose C signatures are fixed and whose C internals call the original Lua formatter/error functions. Its general packed-argument helper follows the measured wasm32 `va_list` pointer ABI, with static assertions. [drl_lua_varargs.pas](../experiments/lua-wasi/pascal-overlay/drl_lua_varargs.pas) packs Lua-supported s/d/c/f/p arguments with C alignment and keeps string conversions alive during the call. It ignores unconsumed arguments like C varargs; one original error call contains an unused extra argument.

[adapt-varargs.mjs](../experiments/lua-wasi/adapt-varargs.mjs) uses the already-tested Pascal lexical scanner to change each original `luaL_error(L,fmt,args...)` call into `luaL_error(L,fmt,[args...])`, retaining argument order and exception location. It replaces only the static external prototypes with Pascal wrappers. Four source tests pass (nesting, comments/literals/declarations, empty args, idempotence). Generation covers all43 original direct calls in7units plus the binding declarations; [manifest](../experiments/lua-wasi/varargs-overlay-manifest.json). Consumers should invoke its exported `rewriteLuaVarargs` after localization/platform source overlays, rather than replacing already-adapted files with the generated pristine-source copies.

Fixed-signature mixed calls compile and link, but initial real execution corrupted Lua tables. An authored C malloc/realloc grow/shrink pattern test passed through Pascal callbacks, ruling out simple byte-preservation failure. Exported LLD globals measured `__stack_pointer=8,388,608` and `__heap_base=8,576,400`; the FPC startup initializes its heap from stack_pointer, so it allocates inside C/FPC static data before the actual heap. Its Lua state pointer8,401,440 confirms the overlap. [mixed-unpatched.map](../experiments/lua-wasi/mixed-build/mixed-unpatched.map) and [measurement record](../experiments/lua-wasi/mixed-layout-evidence.json) retain that evidence. Two separate unrestricted heaps are also unsafe.

[bridge.c](../experiments/lua-wasi/bridge.c) supplies the tested startup fix: standard LLD `--wrap=FPC_WASM_SETINITIALHEAPBLOCKSTART` changes the setter's argument to linker `__heap_base`, retaining original startup order and shared RTL bytes. The exact installed [LLVM Driver.cpp](https://raw.githubusercontent.com/llvm/llvm-project/4bfd08c2d769736841ae4f5705d76fa6daa39027/lld/wasm/Driver.cpp) supports this wrapping and synthetic `__stack_low`/`__stack_high` symbols. [prepare-startup.mjs](../experiments/lua-wasi/prepare-startup.mjs) also creates a shadow si_prc with the same heap-base selection as an alternative; that alternative is not the passing configuration. The probe separately obtains `__stack_low` for System.StackBottom, because the original calculation derives stack bounds from heap start. Corrected startup, fixed/generic formatter adapters, allocator aliases, Pascal callbacks and C-error unwinding execute together in the passing mixed module.

The external FPC WASI linker also omits linklib archives in the measured invocation; [build-mixed.ps1](../experiments/lua-wasi/build-mixed.ps1) supplies explicit `-k<absolute archive>` values. Required archives are Lua, the bridge, WASI libc/setjmp/process-clock emulation and compiler builtins. The passing probe redirects C malloc/free/realloc/calloc and internal libc aliases to one Pascal allocator and exercises OOM, interleaved ownership and GC. Original-game allocation reachability and sustained gameplay remain integration checks.

The tested [drl_c_allocator.pas](../experiments/lua-wasi/pascal-overlay/drl_c_allocator.pas) has no diagnostic tracking tables. It uses Pascal GetMem for the sole memory owner, supplies 16-byte C alignment with a private header, checks multiplication/addition overflow, returns NULL with ENOMEM on allocation failure, preserves the old realloc block until success, and supplies libc internal malloc/calloc/free aliases. Read-only LLVM-nm inspection of the exact SDK archive retained [76 allocator references](../experiments/lua-wasi/allocator-symbol-refs.log), including __fdopen's malloc, fclose's free, locale's __libc_malloc and atexit's __libc_calloc; no __libc_realloc symbol exists in this archive. The archive also defines aligned_alloc and posix_memalign in its allocator object; these are not supplied by this narrow adapter and must remain unselected or receive a compatible shared-owner implementation. [audit-link.mjs](../experiments/lua-wasi/audit-link.mjs) checks the selected object list, all seven allocator owners and absence of independent dlmalloc. The passing map selects 166 libc objects with 13 allocator references, all resolved through the Pascal allocator. The probe alternates C and Pascal strings/dynamic arrays while retaining patterns, exercises libc fopen/fwrite/fflush/fseek/fread/fclose through an isolated `/probe` preopen, requests 128 MiB under a 64 MiB module limit, and runs Lua GC.

LLVM initially optimized the authored OOM fixture to a constant `return 2`, which falsely resembled allocator failure. Retained map/disassembly showed a five-byte function with no allocation. The passing bridge build uses volatile allocator function pointers plus bridge-only `-fno-builtin-malloc`, `-fno-builtin-calloc`, `-fno-builtin-realloc` and `-fno-builtin-free`; these preserve the OOM checks and the interleaved calloc/zero checks. Lua's own compilation flags are unchanged. The source audit enforces these fixture flags so this optimization cannot silently invalidate later coverage.

Pinned FPC `compiler/wasm32/nwasmflw.pas:1352` emits a finally handler for only its own exception tag. The official Lua C configuration uses longjmp, so foreign Lua errors bypass Pascal finally, as native C longjmp does. The mixed probe observes zero finally executions across 2,001 protected error callbacks. Original call-site exception/finally ordering is retained. The adapter's newly introduced managed string conversions receive their own cleanup: it uses Lua 5.1.5 `luaD_rawrunprotected` only while formatting, returns normally to finalize those conversions, then raises the original Lua error/status. This adds no Lua call frame and preserves luaL_where's source level. After each of two 1,000-error/GC batches, the sampled heap is 42,512 bytes; the runner enforces the probe's 4,096-byte growth tolerance.

## Mixed evidence and next exact gate

Its exact [build record](../experiments/lua-wasi/probe-mixed.pas-commands.json) captures the compiler, six archive hashes and `-HeapPatch` command. The bridge archive is `538ff48d2ea87e4bbab861a5351c750365c3260a8b0bedf17fd913e82817c267`; the patched Lua archive is `ff9f4662236e0d6d6873a1078c7635110906b00b82372f2e292ca738a8d42a87`. It executes fixed/packed argument marshalling, actual corrected Pascal debug writes and a 4,097-byte auxiliary buffer, protected callback errors, three structured Japanese diagnostics, one allocator with interleaved file IO, GC and OOM recovery.

[run-node.mjs](../experiments/lua-wasi/run-node.mjs) now checks every expected output field, callback count, ABI size, boolean and heap-growth tolerance; exit0 with placeholder JSON cannot pass. It catches read/compile/instantiate/start failures and closes opened descriptors before recording fresh failure evidence. It verifies module/compiler/archive hashes and the bridge/platform source manifests before executing. [source-audit.mjs](../experiments/lua-wasi/source-audit.mjs) also compares all prepared Lua C/header files against retained pristine sources and explicit patches. [Fourteen light checks](../experiments/lua-wasi/probe-validation.test.mjs) passed without compiling or executing WASM, including missing fields, false-positive results, stale digests, changed/incomplete before-after input snapshots, wrong/ambiguous allocator ownership and incomplete inventory. The recorded runtime predates these additional guards; no second WASM execution is claimed by their tests.

The historical build records omit Pascal-source, RTL-object and link-map hashes. Their current-input/static audit records `complete_build_provenance=false` and states those limits; the strict Node runner requires a fresh captured build before execution. Existing runtime evidence is retained without retroactively certifying its uncaptured inputs. The updated builder captures before/after hashes of the main Pascal source, overlay sources/includes, compiler, archives and all candidate RTL PPUs; it retains the map-selected RTL object hashes and final module/map hashes. It uses `-B` to rebuild authored units, verifies input stability, and the guard compares captured used-object membership against the final map. The new capture path is parsed and light-tested but awaits the parent's next build. Current unchanged Lua sources match the retained pristine tree, but their historical compilation source hashes are also not captured.
