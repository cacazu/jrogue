# DRL corresponding-source release plan

Audit date: 2026-10-02. This plan covers the preserved DRL Pascal/Lua core and the integrated Rust/browser adapters. It is a packaging and rebuild plan, not evidence of a completed game link or a released game. No compiler, linker, browser, server, or upstream build code was executed for this audit.

Current user scope is local HTML with full browser verification through Node. External Sites/deployment is outside scope. Supply sources and notices with the local deliverable; references below to a release concern that local artifact bundle.

The release should provide the preferred editable sources for both deployed WASM modules, their interface definitions, localization inputs, runtime assets, and build/install scripts beside the executable downloads. The existing laboratory `port/dist/source.zip` contains only the earlier Rust migration surface and is insufficient. Upstream code retains its original licenses; the integrated DRL modification is distributed under GPL 2.0, with the separate dependency and art notices retained.

## Permitted source and asset boundary

Build the public source package from an explicit allowlist. Do not copy pristine DRL/engine ZIPs or repository roots wholesale. Those acquisitions are retained privately and contain excluded native payloads. At minimum, reject these six SDK-derived binding files everywhere in the source staging tree, including nested archives:

- `fpcvalkyrie/libs/vfmodconst.inc`, `vfmodtypes.inc`, `vfmodlibrary.pas`.
- `fpcvalkyrie/libs/vsteamconst.inc`, `vsteamtypes.inc`, `vsteamlibrary.pas`.

Also exclude native game executables/libraries, original music/sound directories, unreviewed fonts, `.wad`/native bytecode payloads, commercial JHC assets, `.git` databases, credentials, user saves/logs, and unrelated games. Authored probe executables and generated build products do not belong in the source archive. Original optional integration units under the engine MIT license may be supplied as clearly unused source, but no closed SDK headers/binaries may enter through them. The final link must show that Steam/FMOD and native SDL/OpenGL/audio backends are absent.

Root's current packager retains the exact pinned full FPC source ZIP as a declared development-source companion. Central-directory inspection found **422 original `.o` files and one `.a`, totaling 2,776,818 bytes**; almost all are compiler-test fixtures, with `rtl/palmos/m68k/crt0.o`, `gdbstub.o`, and `libcrt.a` also present. No `.exe`, `.dll`, `.so`, or `.ppu` matches were found in that archive. This immutable upstream fixture exception must be documented and constrained to that archive hash; it is not a blanket permission to include generated binaries or proprietary game payloads. Those objects are not selected by the wasm32 browser build, and no execution of them is requested. Do not claim that this companion archive contains only text source or that every nested object file is absent.

Retain raw Lua sources: native 64-bit compiled Lua bytecode is not a valid wasm32 source substitute. The actual ForceRaw asset allowlist is `config.lua`, `config-browser.lua`, `data/core/**/*.lua`, `data/drl/**/*.lua`, `data/drl/help/*.hlp`, and `data/drl/ascii/*.asc`. The 22 ASCII files are CC BY-SA 4.0 art, credited to Derek Yu and Łukasz Śliwiński with the upstream attribution/source link; they are separate from GPL code and retain their original bytes. Silent browser audio and system fonts are the permitted current platform choice.

## Acquisition and source preparation recipes

Use the existing `tools/acquire-upstream.ps1` for pinned DRL, engine and Lua. It verifies the original commits and Lua checksum. A Git archive made locally and a GitHub codeload archive of the same commit need not have identical archive hashes; compare their extracted content against the source manifest, and record each newly acquired archive's own hash.

The official FPC source URL is already recorded in `toolchain/fpc-wasm-build-manifest.json`:

`https://gitlab.com/api/v4/projects/freepascal.org%2Ffpc%2Fsource/repository/archive.zip?sha=843eb4a6ac1e7c995c0af626c88639e4b1aeaf0d`

The locally preserved archive is preferable to a new download. Root's current `package-core-source.mjs` plan includes it unchanged, avoiding the filtered-tree build-control gaps below. The restore script must safely strip the archive's single recorded top-level directory into `toolchain/fpc-src`, retaining the original ZIP at the path checked by the build script.

If packaging a filtered FPC source tree instead, retain root Makefile/Makefile.fpc, fpmake files/includes and package build-control dependencies as well as units/includes. Each selected package Makefile includes `packages/build/Makefile.pkg`. Host fpmake bootstrap also needs `packages/fpmkunit`, `fcl-process`, and `libtar`, with the existing `paszlib`/`hash`/RTL inputs. The current `build-fpc-wasm.ps1` builds global `packages/fpmake.pp`; its `fpmake_proc.inc` includes every package's `fpmake.pp`, so keeping only eight runtime package trees breaks this step. A filtered route must replace that global stage with a validated per-package fpmake recipe and the explicit host helper closure, or retain the full source/control tree.

The current `build-fpc-wasm.ps1` also insists that the original source ZIP is present at its hard-coded relative location and matches the recorded archive hash. Either distribute that source archive as the explicitly listed companion, or change the offered release rebuild wrapper to verify the filtered source manifest instead. Omitting the archive while leaving that guard unchanged makes the offered recipe fail before compilation.

`tools/acquire-core-dependency-sources.ps1 -IncludeCompilerRuntime` is the executed root-owned acquisition recipe for WASI libc/SDK and the LLVM sparse closure. It uses task-local Git configuration: `pack.threads=1`, `pack.windowMemory=16m`, `core.deltaBaseCacheLimit=16m`, `core.autocrlf=false`, `gc.auto=0`; shallow blob-filtered fetches of exact commits; sparse checkout before detached checkout; and clean-tree/HEAD verification. It does not run downloaded code. The LLVM sparse paths are exactly the seven groups listed above. Avoid a full LLVM archive or recursive SDK submodule update, which would fetch unrelated LLVM/C++ sources.

Equivalent standalone LLVM source preparation, shown as an unexecuted recipe:

```powershell
git init --quiet llvm-source
git -C llvm-source remote add origin https://github.com/llvm/llvm-project.git
git -C llvm-source config pack.threads 1
git -C llvm-source config pack.windowMemory 16m
git -C llvm-source config core.deltaBaseCacheLimit 16m
git -C llvm-source config core.autocrlf false
git -C llvm-source fetch --depth=1 --filter=blob:none origin 895aa2c896ada719451be2e3673c83da8ddf1141
git -C llvm-source sparse-checkout init --cone
git -C llvm-source sparse-checkout set compiler-rt/lib/builtins compiler-rt/cmake compiler-rt/include cmake llvm/cmake llvm/include third-party/siphash
git -C llvm-source checkout --detach 895aa2c896ada719451be2e3673c83da8ddf1141
```

Reject a server response that ignores the blob filter rather than accepting an unexpectedly large transfer. Cone-mode sparse checkout retains parent/root files. Export the checked-out file allowlist without `.git`, record per-file SHA-256 and original Git blob identity, and retain all license-bearing headers. Do not use `git archive HEAD` on a partial clone without path constraints: it can lazily fetch the entire repository and defeat the sparse acquisition.

A small official WASI libc source archive is also available from `https://codeload.github.com/WebAssembly/wasi-libc/tar.gz/2e6fb9d8ee0cdf9e431fbcabe8af3115de000a13`. Record its actual hash and inspect traversal/root/symlink entries before extraction. Archive downloads do not include gitlink contents. Root is acquiring the pinned WASI header-regeneration tree separately; record that completed acquisition before claiming it is supplied.

The installed LLVM 24 compiler used to compile Lua is a build tool at revision `4bfd08c2d769736841ae4f5705d76fa6daa39027`. It differs from the LLVM 23.1.0 source revision used to produce the official SDK 34 builtins archive. Preserve both identities. A compiler binary is not a replacement for the source of the linked builtins archive. Compiler/tool executables are not shipped to browsers by this plan; their whole source trees are not automatically part of game corresponding source. The offered recipe must nevertheless identify obtainable compatible tool versions.

The FPC bootstrap snapshot URL is mutable. Its measured ZIP hash is `1b3eec24dd53ada45b5204237602f7a15b0995f9806311b9e24ab4a998ce36f7`, and bootstrap executable hash is `fc3a8184a70722be726264faac4357fe11851e3edb899be8ced0aea82d4e9cb0`. Preserve this provenance; do not promise that a future download from that URL will yield these bytes. For a portable clean rebuild, validate a supported official bootstrap/compiler route and record it, or explicitly identify the existing compiler source-build prerequisite. This is a toolchain reproduction limitation, not a reason to omit the game/RTL source.

## Concrete packager contract

`tools/package-core-source.mjs` should produce a fresh source staging directory and a machine-readable manifest without building or running game code. A source-only candidate may be staged during the hold; a release-complete flag must require the final artifact/link/rebuild evidence.

1. Verify all input pins, baseline file hashes, localization locks, overlay/ABI manifests and the current Cargo lock. Validate all cached `.crate` hashes before using their source. Snapshot mutable authored source and generated adapted output together; detect concurrent changes rather than mixing localization batches.
2. Preserve the relative layout expected by `adapt-core.mjs`, `localization/generate.mjs`, Lua preparation scripts and the asset packager. Include filtered original `upstream/drl`, permitted `upstream/fpcvalkyrie` bindings, `native/`, `core-overlay/`, and the selected original/adapted Lua sources. Include all generator imports and canonical catalogs/contracts, not only generated Pascal or mirrored locale JSON.
3. Stage clean FPC runtime/package source and selected C dependency source closures under documented paths. Supply the original `si_prc.pp` plus the wrapper/alternative source and notices. Extract a clean FPC baseline from the pinned ZIP to avoid accidentally packaging generated PPUs or altered build-control output.
4. Supply the 23 complete dependency archives, or validate every vendor file against `.cargo-checksum.json` and the original archive checksum. A generated `.cargo/config.toml` may point to a relative vendor directory for `--offline --locked`; do not embed a developer-specific Cargo cache path. Preserve build/proc-macro sources even if their objects are not embedded in WASM.
5. Include complete notices from `port/licenses/`, `toolchain/acquisition/dependency-licenses/` and actual source headers. Add Rust standard-library permissions, compiler-builtins exceptions, selected musl/cloudlibc/fts notices, FPC/LazUtils/Unicode/Paszlib notices, and original ASCII attribution. Preserve original per-file notices and mark modifications with dates/purpose.
6. Write `source-manifest.json` with a schema version, source commits, tool/runtime pins, deployed core/adapter SHA-256, runtime asset-manifest SHA-256, every staged file's path/size/SHA-256/origin/license/modification status, deliberate exclusions, and gate results. Include the final link map and archive-member/source mapping. A hash of a historical probe is not the deployed artifact identity.
7. Use normalized relative paths, reject absolute/drive/`..` paths, links/reparse points and case-folded duplicates, and bound file/total sizes. Stream reads/hashes and archive writing serially so packaging does not require loading full dependency trees into RAM. For the sparse LLVM checkout, constrain Git file-list queries to the selected directories and parent/root build/license files rather than capturing the entire monorepo index. Companion source archives or bounded parts are acceptable if the index lists all parts/hashes and supplies an ordinary reconstruction/extraction recipe.
8. Reopen the resulting archive(s), verify the archive entry set and every byte hash against the source manifest, scan exclusions including nested archives with the exact documented FPC fixture exception, and assert that every required input above is supplied. Keep corresponding source and complete license notices beside the locally delivered WASM. Do not substitute an upstream link or an unfulfilled future source offer for the selected complete source package.

The final game release wrapper should build the Rust WASM directly and then run the original-core preparation/dist steps. The existing `port/build.ps1` copies the laboratory index/app/style and runs the old laboratory source packager, which overwrites `build.json` and `source.zip`. Do not call that unchanged script as the last production packaging step.
