# 操作記録と集計

全操作の記録、操作の多い順の集計、固定シードの再攻略に使う。既存の実行記録がある場合は、その形式と再生手段を優先する。新規記録ではメタデータと逐次追記できるJSONL等を分ける。

## メタデータ

対象作品・原作の版、使用したビルドと識別情報、配信元、シード・名前、試行ID、勝利条件、死亡・ロード・新規開始の制限、開始条件、参照した攻略と事前記録を残す。録画する場合は、動画の開始に対応する操作番号と経過時刻も持つ。

## 操作の一単位

一つの意図に対する入力と、その後に成立した状態・結果を一件にする。keydownとkeyupを二操作と数えない。長押し・走行・数値反復は送信方法と実際の進行量を残し、ボタン押下回数、消費された入力数、ゲームのターン数を混同しない。

各操作には次を持たせる。

| 項目 | 記録するもの |
| --- | --- |
| 順序と時刻 | 単調増加する操作番号、試行開始からの経過時刻。録画がある場合は対応する動画時刻 |
| コンテキスト | 通常コマンド、品物、方向、文字、確認、ページ送り、設定等、送信前の待ち |
| 入力 | 操作名、キー・修飾キー・文字列、タッチ対象。画面座標だけでなく対象の意味を残す |
| 前後状態 | 公開された階・座標・HP・空腹・状態異常・装備等、判断や再生照合に必要な値 |
| 結果 | 実際のログ、公開状態の差、次の入力待ち、死亡・ロード・新規開始・勝利等の事実 |
| 分類 | ゲーム操作、後続選択、画面操作。ターン消費は観測できた実数、分からなければ未確認 |
| 理由 | 危険や重要な判断に対する、現在の観測と今後の脅威に基づく説明 |

ゲーム内のアイテム文字は持ち物の変化で変わり得る。文字だけでなく、当時公開されていた表示名・数量・装備状態と選択候補も残す。知らない正体を内部値から埋めない。

実際の形は既存の記録APIに合わせる。例えば方向指定は、投げるコマンドと方向選択を別の番号で記録し、それぞれ送信前後の入力待ちを残す。テスト用接続を使う場合も、プレイ入力は通常の入力経路へ送り、公開状態の読み取りとゲーム内部の診断を分ける。内部値を読む診断は攻略判断に使わない。

## 再攻略と動画への対応

- 再生前にビルド・シード・開始条件を照合する。別版で再攻略する場合はその差を明記する。
- 送信前後の公開状態と入力待ちを記録に照合する。差が出たらその操作番号と観測を残し、止めて再計画する。
- 動画用には経過時刻と操作番号を保ち、長い無操作待ちも区別する。事前記録を使った先読みは解説でも明示する。
- 操作一覧や集計は逐次記録から生成する。動画の見た目や記憶だけで操作数を推計しない。

## 操作数の集計

集計対象と単位を先に示し、入力一件を二つのコマンドへ重複計上しない。移動の各方向、走行、待機、探索、装備・使用・投射、階段などを実際の操作名で数え、件数の降順にする。後続の品物・方向・確認入力と、設定・表示の操作は別分類で示す。

連続移動のボタン押下数と進んだ歩数、ゲームターン数は別の量として扱う。死亡・ロード・新規試行の件数は別に実数を出し、「死亡なし」「ロードなし」の条件の根拠にする。

記録をまとめる前に、操作番号の欠落・重複、入力待ちに対する不適切な入力、重要な結果の未観測を確認する。実行していない操作や未確認の後続処理を、記録の穴を埋めるために作らない。
