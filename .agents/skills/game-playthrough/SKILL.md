# ゲーム攻略と操作記録

攻略情報を実際の判断へ使い、指定された条件でゲームの勝利までプレイする。攻略を説明するだけの依頼では説明にとどめ、実プレイの依頼では結果と操作記録を残す。

## 対象と成功条件を決める

- 適用される `AGENTS.md`、対象作品のREADME、操作と原作仕様を読む。作品・版・ビルド、シード、勝利条件、死亡・ロード・新規試行の制限、操作記録と録画の要否を依頼から確定する。
- 指定されたシードと記録を使い、事前記録に基づく判断はその旨を明記する。指定がなければ再現可能なシードと条件を選んで示す。実装や版が違う記録をそのまま再生しない。
- 実プレイには通常のゲームを使う。fixture、無敵化、状態編集、乱数の差し替え、未公開マップや未識別アイテムの内部値を攻略の手段にしない。
- ブラウザー操作はPlaywrightで行い、既存の起動・入力・テスト用接続を調べて利用する。表示確認にはスクリーンショットを使う。録画は依頼された場合に作る。

## 役に立つ攻略を調べる

- 対象の版に合う公式マニュアル、原作コード、英語圏を含む攻略サイトを検索し、該当する本文を開いて読む。参照先・対応する版・使った判断を記録する。
- アイテム一覧や敵の数値だけで済ませず、序盤から終盤・帰還・勝利まで、どの状況で戦う・逃げる・探索する・資源を使うかが書かれた攻略を探す。
- 攻略サイトの立ち回りと、公式資料・現行コードで確かめる効果や数値を区別する。作品・版が違う助言、未確認の仕様、今回の観測を混同しない。
- 集めた情報を、次の階や終盤の脅威に備える行動へ変換する。例えば敵の特殊能力に対する装備と位置取り、退路、回復・食料・逃走手段の温存、未識別品を試す条件、目的物取得後の帰還計画を立てる。

## 観測してから行動する

- 操作前に、公開された地図、HP等の状態、空腹・状態異常、装備・持ち物、最新ログ、入力待ちを確認し、行動の目的と中止条件を決める。
- 危険な状況では一操作ごとに結果を確認する。連続入力や走行は安全を確認できる区間に限り、敵の出現、被弾、状態変化、移動停止、別の入力待ちで止める。キーを長く送り続けて観測を省略しない。
- 品物・方向・手・文字・確認等の待ちには、表示された候補と現在の入力コンテキストに従う。コマンドを押した後の選択・効果・マップ復帰まで確認し、次の操作を送る。
- 回復や逃走が間に合う条件を具体的に見積もる。敵の攻撃力・連続攻撃・特殊効果を見ずに殴り合ったり、危険な未識別品を理由なく使用したりしない。
- 以前の記録がある場合も、その時点の公開状態・入力待ちと結果を照合して進む。初めて差が出た場所で再計画し、先のキー列をそのまま流さない。
- 攻略中の不具合は操作と前後状態を記録する。修正も依頼されている場合は、再現と根本原因の調査を先に行う。修正前後のプレイ記録とビルドを分け、条件が変わったプレイを元の成功として扱わない。

## 操作と判断を残す

操作記録・集計・再攻略が必要な場合は、[記録形式と集計の基準](references/recording.md)を読む。既存の記録形式を優先し、不足する入力待ち・後続選択・結果・条件の識別情報を補う。

- 操作の順序、実際に送った入力、待ちの種類、前後の公開状態、結果を逐次記録する。ゲームのターンを進める操作と、設定・表示・一覧などの画面操作を区別する。
- 全操作の記録を求められた場合は、移動だけでなくアイテム・方向・取消・ページ送り・保存・ロード等も残す。操作後の観測を記録せず「キーを送った」だけで成功扱いしない。
- 「なぜ今これをするか」は、確認した事実と先の脅威を結び付ける。戦闘・資源使用・装備変更・進路変更・危険な判断には理由を添え、単調な安全移動には必要以上の説明を繰り返さない。
- 失敗試行も記録し、無断のロードや試行の隠蔽をしない。新規試行が許可されているときは別の試行IDを付け、成功した試行の条件と全試行の結果を分けて示す。

## 勝利を確認して報告する

その作品の目的物・帰還・エンディング等の勝利条件を最後まで満たし、実際の勝利画面、結果、利用可能な終了状態を確認する。階の到達、終了ウインドウ、操作列の最後に来たことだけをクリアの根拠にしない。

成功時は作品・版・シード・試行ID・勝利結果、死亡とロードの実数、記録の場所を示す。操作集計が依頼された場合は記録から算出して件数の多い順に出す。録画が依頼された場合は、完成したファイルの再生と内容も確認する。未達の場合は実際の到達点・失敗理由・残る条件を示し、クリア済みと報告しない。
